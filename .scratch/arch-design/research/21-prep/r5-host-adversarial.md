# Ticket 21: host-boundary adversarial review (r5)

Scope: L1–L3, L10, L14–L17. [V] The ledger records these as leaning hypotheses, not approved decisions (`.scratch/arch-design/research/21-prep/decisions-ledger.md:1-30`). [H] Recommendations below are design judgments, not observations. No source changes or checks are part of this review.

## Critical corrections to r4

- [V] `r4-host-workspace-alternatives.md:94-110,458-461` contrasts `HashMap<String,String>` with a typed snapshot and recommends an unspecified `EnvMap` input; its sketch stores a `HashSet<String>` of ignored names (`r4-host-workspace-alternatives.md:350-361`). **A Unicode-only map would not be behavior-preserving** for path-valued environment variables: production obtains `HOME`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `TRACES_STATE_DIR` with `var_os` and converts directly to `PathBuf` (`src/dirs.rs:56-77,90-116,125-162,191-196`), and splits the OS-valued ceilings with platform-aware `split_paths` (`src/env_vars.rs:6-16`). Rust explicitly distinguishes a missing variable from invalid Unicode for `var` and preserves OS strings in `var_os` ([std::env::var](https://doc.rust-lang.org/std/env/fn.var.html), [std::env::var_os](https://doc.rust-lang.org/std/env/fn.var_os.html), [std::env::split_paths](https://doc.rust-lang.org/std/env/fn.split_paths.html)). [H] Construct the typed snapshot from a *plain map of `OsString` values*, keyed by known static names; convert to `String` only for `TRACES_IGNORED_DIRS`, where today's `var` deliberately ignores a non-Unicode value (`src/env_vars.rs:25-44`). Do not invent strip/reject normalization: current delimiters are `:` and `,`, whitespace is trimmed on each fragment, empty fragments are dropped, defaults are additive, and non-Unicode filenames cannot match the `String` ignore set (`src/env_vars.rs:18-44`). If broadening that contract to `HashSet<OsString>`, record a separate intentional behavior change, not a snapshot refactor.
- [V] `r4-host-workspace-alternatives.md:150,470` recommends `ArcSwap<Arc<Inner>>`, but the primary definition is `type ArcSwap<T> = ArcSwapAny<Arc<T>>` ([arc-swap 1.9.3 API](https://docs.rs/arc-swap/latest/arc_swap/type.ArcSwap.html)); `ArcSwap<Arc<Inner>>` therefore stores `Arc<Arc<Inner>>`, an unnecessary second allocation/indirection. [V] `arc-swap` is not among current production dependencies (`Cargo.toml:119-152`). [H] A host that actually needs concurrent replacement could use `RwLock<Arc<Workspace>>` and clone under a short read lock, publish under a short write lock; std documents the distinct reader/writer accesses ([std::sync::RwLock](https://doc.rust-lang.org/std/sync/struct.RwLock.html)). Only measurable read-lock contention justifies an added lock-free dependency (`ArcSwap<Workspace>`, *not* `ArcSwap<Arc<Workspace>>`). A host with single-threaded request dispatch can own and replace `Arc<Workspace>` directly.
- [V] `r4-host-workspace-alternatives.md:163-176,453-460` conflates a **registry identity**, a **config generation**, and a **persistence namespace**. A trust entry is canonical-path keyed (`src/file_tracker.rs:87-112,428-454`), the workspace `Config.root` comes from the discovered local root (`src/config/service.rs:95-111`; `src/config/model.rs:46-55`), and the index DB resides *inside that root* at `.traces/index.redb` (`src/index/mod.rs:47-48`; `src/index/store.rs:145-188`). The persisted fingerprint selects ten config settings but excludes root and schema directory (`src/index/fingerprint.rs:37-81,136-143,156-201`); it also does not include ignored directories (`src/env_vars.rs:18-44`). [H] Root identity alone suffices for independently rooted workspaces inside one host policy. At the *same root*, different state homes require isolated trust-store handles (but need not force a second index), different config homes may produce different effective configs, and different ignore sets can produce different indexed row scopes; only differing row semantics/scopes require separate persistence or one serialized policy owner. Adding fields to an in-memory key never isolates a shared `root/.traces/index.redb`. A config digest is a revision/invalidation signal, not a stable workspace identity. A held object need not clone the whole `HostInputs` if it already holds its derived locator/store/ignore dependencies.
- [V] The present query path resolves candidate paths, then reads notes, files, and inlinks in separate calls (and parallel branches) before assembling rows (`src/query/service.rs:130-169`), while full rebuild clears/repopulates tables under a write transaction (`src/index/store.rs:787-804`). [H] Thus even an in-memory registry keyed by `(root, policy)` is insufficient if both objects write the same physical DB: one request could read candidate paths from one policy generation and rows from another, or retain mismatched scope. An alternative to independent persistence is a **single policy owner per root** with serialization covering refresh *and* materialization, not just the swap itself. Whether true same-root/multi-policy concurrency is supported belongs to [workspace host](../../issues/30-workspace-host-and-composition.md#L7-L25) and [freshness](../../issues/25-index-freshness-and-invalidation.md#L9-L24).
- [V] R4's typestate example is a separate miniature (`r4-host-workspace-alternatives.md:116-132`) and its claim that an `Arc` swap automatically solves live config changes (`:138-155`) has no production enforcement. Present trust is checked once at `ConfigService::build`: local file `into_trusted` verifies hash and returns verified content before parsing (`src/config/service.rs:95-111`; `src/config/file.rs:197-235`; `src/config/trust.rs:240-260`). [H] If a long-lived workspace holds that parsed config across an edit or `untrust`, replacement needs a **freshness/revocation trigger and re-open policy**; a swap is merely publication. Watcher notification alone cannot prove that the current trusted content still matches the trust-store baseline. The precise revocation guarantee is an unresolved security/lifecycle decision for [config ownership/lifecycle](../../issues/22-config-ownership-and-lifecycle.md), not a conclusion that typestate or a held `Arc` settles it.
- [V] The trust gate is specifically **local config**; the optional global config takes a separate direct read/parse path after local verification (`src/config/service.rs:95-111`; `src/config/file.rs:273-308`). [H] A bound workspace must name which config sources it snapshots and which source's edits/revocation are protected by trust; calling all config “trust-gated” would overstate the actual authority. A global-config edit can change the next reopened workspace without any local trust-store transition, so publication triggers must include both file sources.
- [V] R4 calls 12 cited precedents and three compiled sketches outstanding (`r4-host-workspace-alternatives.md:475-500`). [H] None of those claims is established by that report. The source above and primary Rust API references, not its uncompiled sketches or `/tmp` Cargo copy, ground this review.

## Decision-by-decision adversarial verdicts

### L1 — several independent workspaces in one process: **retain the invariant, narrow the mechanism**

[V] [Forward-consumers ticket](../../issues/17-grilling-forward-consumers-and-design-pressure.md#L35-L58) commits LSP readiness and a likely MCP seam, but explicitly refuses speculative multi-workspace machinery (`:65-75,97-101`). The current `Config` contains its own root (`src/config/model.rs:46-55,77-82`), whereas `CONFIG_HOME` and ignore names are process-global (`src/dirs.rs:90-116`; `src/env_vars.rs:23-44`). [H] Keep *independent policy* as a correctness constraint, not a mandate for a multi-root manager or an all-purpose workspace ID. The adapter/host selects a policy and absolute start path per workspace; domain/index operations use only bound inputs. Root+host namespace is relevant only if the same root can be opened under distinct host policies; an index file at `root` defeats an in-memory key alone (`src/index/store.rs:154-188`).

**Strongest alternative:** [H] a process-wide immutable startup policy plus workspace-specific config is leaner and likely sufficient if all roots in an LSP intentionally share config home, state root, and ignored names; it avoids needless per-workspace copies while keeping different `Config`s and zones. **Boundary/owner:** adapters own policy assignment and workspace registry, `ConfigService` owns discovery/trust stores, index owns persistence; [workspace host](../../issues/30-workspace-host-and-composition.md#L7-L25) decides if a registry exists, [path/capability](../../issues/29-path-and-capability-model.md#L7-L25) decides canonical identity and same-root aliases. **Flip fact:** [H] a real LSP/MCP request stream that opens the *same canonical root* under two distinct ignore or trust-store policies, simultaneously, would require policy-isolated index persistence rather than just a host-scoped registry.

### L2 — one `HostInputs` snapshot: **accept typed derived inputs, reject a Unicode-only env map and implicit path semantics**

[V] Today the config locator reads ceilings and global home from globals (`src/config/discovery.rs:31-47,73-83`), but the `ConfigService` instance only stores tracker/trust stores and its static `trust_subjects` makes a fresh ambient locator (`src/config/service.rs:35-41,74-76,171-205`); both trust subtree and index scan invoke the same ambient ignore predicate (`src/config/discovery.rs:141-175`; `src/index/service.rs:421-440`). Unit tests can inject a locator (`src/config/discovery.rs:50-61`; `src/config/service.rs:343-369`) and stores (`src/config/service.rs:183-193`) separately, already showing the seam. [H] Resolve OS vars at the adapter into a typed, self-contained set of state root, global config home, ceilings, and ignored names; inject the same chosen values into **both** walks and trust discovery. Construction from a plain OS-value map permits two different policies in one process without `set_var` (Rust 2024 makes mutation of environment in multithreaded Unix programs unsafe: [std::env::set_var](https://doc.rust-lang.org/std/env/fn.set_var.html)).

[V] A subtle break: code documents ceilings as absolute but merely parses them (`src/env_vars.rs:6-16`), and path-valued overrides are taken as raw `PathBuf` with no absolute check (`src/dirs.rs:191-196`). [H] A relative override in an otherwise injected snapshot still resolves at later filesystem I/O against *then-current process cwd*, contradicting L3; require an explicit absolute base at capture or reject relative path overrides with a typed error, choosing the compatibility policy in [config ownership](../../issues/22-config-ownership-and-lifecycle.md#L9-L28) and [path/capability](../../issues/29-path-and-capability-model.md#L7-L25). Preserve platform HOME/XDG/APPDATA precedence (`src/dirs.rs:56-162`) and the Unicode ignore-name behavior unless independently changed. Capturing only named variables via `var_os` is enough for current inputs; `vars_os` explicitly offers a process snapshot if true all-at-once capture is required ([std::env::vars_os](https://doc.rust-lang.org/std/env/fn.vars_os.html)).

**Strongest alternative:** [H] promote existing `ConfigLocator::new` and `ConfigService::for_test` into production constructors, inject an ignore predicate/set into the two walkers; no extra `HostInputs` type is necessary if the callers can wire these without accidentally mixing authorities. **Boundary/owner:** adapter captures OS values; `config` resolves host path precedence and holds locator/stores; `index` receives ignore set (not a global); [config ownership](../../issues/22-config-ownership-and-lifecycle.md#L9-L28) locates `dirs`/`env_vars`, [freshness](../../issues/25-index-freshness-and-invalidation.md#L9-L24) decides whether ignore changes require a recorded index identity. **Flip fact:** [H] demonstrate an operation requiring these four derived inputs together that cannot be composed safely via narrow constructors; then a typed aggregate earns its existence over independent arguments.

### L3 — explicit start path and delete `CwdGuard`: **accept with a precise boundary**

[V] The production cwd read is the `Cwd::new()` wrapper in `src/cli/cwd.rs:19-40`, used for `load_config`, optional trust target, and init (`src/cli/mod.rs:236-254,522-543`; `src/cli/init.rs:34-55`). `ConfigLocator::project` already accepts `&Path` (`src/config/discovery.rs:63-83`). `CwdGuard` and its mutex are `#[cfg(test)]` (`src/cli/cwd.rs:50-126`), so removing them changes tests rather than a production contract. Nextest runs each test in a separate process ([nextest execution model](https://nexte.st/docs/design/how-it-works/)); `cargo test`, by contrast, runs tests of one binary in parallel in the same process (same source). [H] Core's *workspace opener/discovery* takes one explicit absolute start path; operations on a bound workspace should take **no repeated start path** (they have `Config.root`). This tightens L3's overly broad “every library operation” and avoids repeated path allocation/discovery. The adapter reads cwd only if it needs a default or must resolve a relative user path against its own captured cwd; never mutate process cwd to run a workspace operation.

**Strongest alternative:** [H] leave `CwdGuard` for CLI adapter-level `cargo test` tests: it correctly serializes guarded test mutations even if nextest isolates them; discard it only when those tests can be rewritten to pass a start path (and retain a real-binary cwd test). **Boundary/owner:** CLI owns cwd default and `-C` decision; workspace opener owns discovery; [path/capability](../../issues/29-path-and-capability-model.md#L7-L25) owns path spelling, symlink and confinement; [workspace host](../../issues/30-workspace-host-and-composition.md#L36-L43) decides exposed start-path API. **Flip fact:** [H] a valid library use case requiring *discovery from a different directory after opening the same workspace* would justify a per-call start path rather than a bound root.

### L10 — explicit dialog policy: **accept, but the current CLI fallback is part of compatibility**

[V] Non-TTY terminal `text` yields default or empty, `confirm` default or false, `select` index 0, and `multi_select` empty (`src/dialog/terminal.rs:43-108`). `PresetDialogProvider` **also** defaults to index 0 when its select queue runs dry (`src/dialog/preset.rs:26-35,171-235`), so simply calling it “preset answers” does not imply exhaustive scripted answers. On the other hand, CLI template *name picker* already explicitly errors `NotInteractive` when the provider says no (`src/cli/template.rs:236-260`), and `--no-input` explicitly selects the fallback provider (`src/cli/template.rs:64-70,167-177`). Template `ui.*` delegates through `DialogProvider` (`src/template/engine/ui.rs:77-129`); `NotInteractive` already exists (`src/dialog/error.rs:43-52`). [H] Distinguish **RequireAnswers** (headless, errors on missing answers) from **UseDefaults** (explicit compatibility policy) and interactive terminal, without multiplying unused trait shapes. The host chooses once per operation/render; only the CLI adapter asks whether stdin is a TTY. A bare `PresetDialogProvider` must not serve as strict noninteractive input unless exhaustion errors.

**Strongest alternative:** [H] keep the existing `DialogProvider` polymorphism and add only a strict provider to the host, while CLI keeps its existing fallback behavior: sufficient abstraction already exists (`src/dialog/mod.rs:37-52`, `src/dialog/error.rs:43-52`). **Boundary/owner:** CLI owns `--no-input`/TTY and legacy exits, template owns the `ui.*` contract, MCP owns missing-input rejection or explicit elicitation; [workspace host](../../issues/30-workspace-host-and-composition.md#L9-L20) owns dispatch and [forward consumers](../../issues/17-grilling-forward-consumers-and-design-pressure.md#L35-L41) forbids building speculative MCP interactions. **Flip fact:** [H] a concrete MCP host that needs template defaults as its documented behavior would make strict failure optional rather than the default, without reviving silent choice in otherwise strict mode.

### L14 — workspace object and wholesale replacement: **retain a cohesive object; split persistence and authorization lifetimes**

[V] CLI composes index refresh, conditional schema load and query (`src/cli/mod.rs:335-365,470-502`); template construction independently loads schema and builds an indexer (`src/template/engine.rs:125-163`). `Config` is a cloned resolved root/config aggregate (`src/config/model.rs:46-55,67-82`); `IndexerService::from` owns clones of tasks/frontmatter and a boxed fingerprint (`src/index/service.rs:38-59`). A config drift may rebuild the full index and warn but return an in-memory result if persisting fails, whereas `refresh_store` propagates the persist error (`src/index/service.rs:174-189,279-305`); index rows/fingerprint are written in one transaction (`src/index/store.rs:787-804`). [H] A `Workspace` that composes derived query/index/schema services is justified by the real duplicate construction, but **do not** rebuild persisted rows or open a new DB solely because the in-memory config/schema snapshot changes. Build the replacement against the same persistent store, let index fingerprint decide row invalidation, and publish one coherent generation for subsequent requests. Current requests may finish on the old immutable generation; revocation semantics require explicit separate choice.

[V] Ticket 20 says schema definitions never enter the persisted index/fingerprint and class bindings are expanded at query time (`.scratch/arch-design/issues/20-schema-note-typing-and-validation.md:49-64,310-326`); current index fingerprint excludes schema directory (`src/index/fingerprint.rs:136-143,156-201`). [H] Wholesale **schema service replacement** on a schema edit need not refresh/rebuild index *unless* the configured class-field name changes or a different persisted field actually depends on the schema. Recreating heavyweight schema/template engines eagerly on each config event may be wasteful; lazy construction within each immutable workspace generation remains consistent. `RwLock<Arc<Workspace>>` under a host, or plain ownership in a single-thread host, beats `ArcSwap<Arc<Inner>>` by default ([std::sync::RwLock](https://doc.rust-lang.org/std/sync/struct.RwLock.html); [arc-swap alias](https://docs.rs/arc-swap/latest/arc_swap/type.ArcSwap.html)).

**Strongest alternative:** [H] stateless app use-case functions over `&Config`, `&SchemaService`, `&IndexerService`, etc., with a host owning and assembling a per-request bundle; for pure `check_note` this avoids a held object and tracks ticket 20's *unratified* functions-only assertion (`.scratch/arch-design/issues/20-schema-note-typing-and-validation.md:66-79`; `.scratch/arch-design/research/21-prep/decisions-ledger.md:42-45`). **Boundary/owner:** app layer owns composed operations, host owns generation publication and liveness, config owns trust/reload, schema owns checker, index owns persisted row freshness. [Workspace host](../../issues/30-workspace-host-and-composition.md#L7-L43), [config lifecycle](../../issues/22-config-ownership-and-lifecycle.md#L9-L28), [index freshness](../../issues/25-index-freshness-and-invalidation.md#L9-L45), and [crate topology](../../issues/32-crate-topology-and-public-surface.md#L32-L50) **must** reconcile those seams before L14 is binding. **Flip fact:** [H] a real headless operation needs only `&Config` plus pure checker and reuses none of the derived services; then compose that operation as a function instead of forcing it through a large workspace object.

### L15 — Clippy plus lexical source scan: **reject the claim this enforces elimination**

[V] Current `clippy.toml:89-98` bans `current_dir`, `set_current_dir` and `canonicalize`, not env reads or temporal sources. Clippy's `disallowed-methods` accepts **fully qualified paths** and names individual methods/functions, not wildcard path families ([Clippy configuration](https://doc.rust-lang.org/clippy/lint_configuration.html#disallowed-methods), [lint specification](https://rust-lang.github.io/rust-clippy/master/index.html#disallowed_methods)). Therefore ledger L15's spelling `std::env::var*` is not a single valid wildcard entry (`.scratch/arch-design/research/21-prep/decisions-ledger.md:28`). [H] Ban each chosen leaf (`var`, `var_os`, `vars`, `vars_os`, cwd, explicit time/zone constructors) and allow exact adapter callsites; a lexical scan is supplementary *inventory*, not an enforceable proof. It misses renamed imports, wrapper methods, proc-macro expansions, alternate clock/zone APIs, and dependency-owned reads, and can flag comments/strings. Add architecture tests that exercise two differently configured workspace inputs in one process and verify no cross-policy leak; behavior is a stronger guard than naming convention.

**Strongest alternative:** [H] centralize all acquisition behind one explicitly audited adapter module and use only the resolved-path Clippy lint plus a compact, deliberately incomplete source inventory. A custom HIR-based audit across all core crates might become warranted if an actual escaped ambient read survives this rule. **Boundary/owner:** [crate topology](../../issues/32-crate-topology-and-public-surface.md#L7-L37) decides what is a core crate versus adapter; lint gates apply to **core's production target**, not a file named `src/cli` after the CLI moves to another crate. **Flip fact:** [H] show a real forbidden call that passes Clippy and behavior tests while requiring a second enforcement method; then AST/HIR audit becomes justified. No linter, build or test was run in this review.

### L16 — delete guards and HOME override: **accept cutover conditional on genuine injected tests**

[V] `HOME` is a test-only constant path (`src/dirs.rs:80-82`) but the config/state overrides still consult `XDG_*` and `TRACES_STATE_DIR` (`src/dirs.rs:90-116,125-162`), and ignore/ceilings still consult live env (`src/env_vars.rs:6-44`). `CwdGuard` is test-only (`src/cli/cwd.rs:50-126`) and the CLI test fixture calls it to run the real dispatcher (`src/cli/mod.rs:598-619`). The child-process e2e harness already sets isolated homes/state/TZ and explicitly opts into ceilings and ignored dirs (`tests/e2e/support.rs:1-30,47-72`); this is a good real-binary oracle. [H] Replace unit/integration fixtures with explicit OS-map-to-derived-policy inputs and absolute start paths; retain a small subprocess suite for real env/cwd behavior, including a non-Unicode path value on Unix/Windows where feasible. Then delete the test HOME override and guarded cwd mutation; this removes a false sense that only HOME affects tests. Do not equate nextest's process isolation with hermetic env/filesystem paths (`src/dirs.rs:80-82,90-162`; [nextest model](https://nexte.st/docs/design/how-it-works/)).

**Strongest alternative:** [H] leave the `CwdGuard` in CLI-only adapter tests for developers invoking `cargo test`; it solves those tests' in-process cwd races, while all core tests can be independent. **Boundary/owner:** test fixtures at the app and adapter boundary, [config lifecycle](../../issues/22-config-ownership-and-lifecycle.md#L24-L28) owns remaining dirs hooks. **Flip fact:** [H] if every CLI adapter test runs through a spawned binary or receives an explicit start path, a cwd-mutating guard has no remaining user.

### L17 — ambient residue only at adapter: **reject as exhaustive; name render entropy and filesystem liveness**

[V] Template code directly invokes `Uuid::new_v4()` (`src/template/engine.rs:219-224`), registered into render environment (`src/template/engine.rs:159-165`); the UUID crate explicitly documents this as random ([uuid 1.26.1 API](https://docs.rs/uuid/1.26.1/uuid/struct.Uuid.html#method.new_v4)). It is a non-repeatable input below the CLI adapter and is missing from L17's exceptions (`.scratch/arch-design/research/21-prep/decisions-ledger.md:30`). [H] Treat UUID generation as a separate optional **render capability**: either explicitly exempt entropy (and say the “everything else” claim is false) or inject a generator at template construction if deterministic templates and test isolation matter. This is not a reason to add entropy to the host-inputs snapshot; one UUID per invocation cannot be frozen at workspace open. [V] Templates also read files through a loader registered at construction (`src/template/engine.rs:109-124`), and index refresh re-scans files each time (`src/index/refresh.rs:337-358`), so “everything else passed explicitly” cannot mean a world snapshot. [H] Narrow L17 to *process-global policy* reads; mutable filesystem is an explicit workspace resource with separate freshness/authorization rules.

**Strongest alternative:** [H] UUID generation remains deliberately ambient inside its narrowly documented template API; it is not a workspace-policy decision, and the need to preserve a random default outranks deterministic replay. **Boundary/owner:** template ticket [template engine boundary](../../issues/28-template-engine-boundary.md#L7-L25) decides entropy, CLI/LSP adapters own terminal/logging/panic hooks, [freshness](../../issues/25-index-freshness-and-invalidation.md#L25-L45) owns on-disk liveness. **Flip fact:** [H] a reproducible template-render contract or shared generation seeded per request would require explicit entropy injection. Do not claim `NO_COLOR`, logging subscriber or thread-pool setup is currently implemented here merely because the ledger lists them; their actual callsites were not established in this host slice.

## Cross-ticket conflicts to settle before locking

1. [V] [Forward consumers](../../issues/17-grilling-forward-consumers-and-design-pressure.md#L35-L41) refuses speculative multi-workspace support. [H] L1 is a prohibition on globals in core, **not** a demand that ticket [workspace host](../../issues/30-workspace-host-and-composition.md#L7-L25) implement a multi-root registry now. If same-root/different-policy concurrent sessions are supported, index persistence and workspace identity must be decided together (L1, L2, [freshness](../../issues/25-index-freshness-and-invalidation.md#L9-L24), [path/capability](../../issues/29-path-and-capability-model.md#L7-L25)).
2. [V] Ticket [schema validation](../../issues/20-schema-note-typing-and-validation.md#L49-L64) excludes schema definitions from index/fingerprint while L14 says replace a workspace on schema changes; [config lifecycle](../../issues/22-config-ownership-and-lifecycle.md#L9-L28) is still open. [H] An in-memory schema-generation swap and persistent index invalidation are different events. Ticket [freshness](../../issues/25-index-freshness-and-invalidation.md#L78-L87) must not accidentally add schema-file digests to index fingerprints to satisfy L14.
3. [V] Ticket [schema validation](../../issues/20-schema-note-typing-and-validation.md#L66-L79) says use cases are free functions; L14 says held workspace object; ledger explicitly labels functions-only unratified (`.scratch/arch-design/research/21-prep/decisions-ledger.md:42-45`). [H] [Workspace host](../../issues/30-workspace-host-and-composition.md#L45-L62) must select a coherent hybrid (object for I/O/service composition, pure check functions inside schema/app); [crate topology](../../issues/32-crate-topology-and-public-surface.md#L32-L50) must expose only outward-facing entry points, not an ever-growing omnibus context.
4. [V] Current trust content is verified once before parse (`src/config/file.rs:214-235`; `src/config/trust.rs:240-260`) and config service loads from an ambient locator (`src/config/service.rs:74-76`). [H] L14's held trusted config, L2's separate snapshot and [config lifecycle](../../issues/22-config-ownership-and-lifecycle.md#L24-L28) must specify whether revoke/edit invalidates **already running** operations, *next* request, or only re-open. An `Arc` swap does not implement trust invalidation; a file watcher is a hint, not the baseline check.
5. [V] Paths may keep original noncanonical spelling after confinement (`src/path.rs:140-190`), while trust-store target keys canonicalize (`src/file_tracker.rs:428-454`) and index DB is root-relative (`src/index/store.rs:154-188`). [H] L3's explicit start, L1's identity, L2's relative override semantics and [path/capability](../../issues/29-path-and-capability-model.md#L7-L25) must jointly settle canonical discovery identity versus operation path without claiming lexical validation is a race-free capability.
6. [V] [Crate topology](../../issues/32-crate-topology-and-public-surface.md#L32-L50) places the CLI as one consumer of core; current CLI chooses TTY fallback and `--no-input` (`src/cli/template.rs:64-70,167-177`). [H] L10 policy belongs at adapter/host, template receives only a provider. L15's allowed-module lint list must follow the actual crate boundary after the split, not exempt all uses in a future core module named `adapter`.

## Verification boundary

[V] All repository citations above come from read-only source inspection; primary references are official Rust/Clippy/nextest documentation and arc-swap's published type definition. [H] No compile, test, lint, benchmark, non-Unicode fixture, same-root concurrent refresh, or live trust revocation was executed; their behavior is proposed as falsification evidence, not claimed as measured. [H] Smaller option skipped: no new ambient-context framework, multi-root registry, custom HIR lint, ArcSwap dependency or typestate opener is justified solely by these observations.

# Temporal, query, and template adversarial review (ticket 21, L4-L9, L12-L13, L18)

Evidence key: [V] directly read repository source or primary documentation; [H] deduction or proposed counterexample requiring an implementation decision. The ledger's decisions are hypotheses, not approved choices. No source, ticket, map, or ledger changes were made.

## Verdict: three contracts collide

- [V] [Ticket 19's resolved Answer](../../issues/19-coercion-and-comparison-policy.md#L72-L99) separates loose filter equality, bracketed relational filters, and total sort keys, but its literal rule calls `[s,e]` **inclusive** and says `==` iff `s <= x <= e`, `<` iff `x < s`, `<=` iff `x <= e`, `>` iff `x > e`, `>=` iff `x >= s` ([ticket 19:125-130](../../issues/19-coercion-and-comparison-policy.md#L125-L130)). [V] L13 calls the local day `[s,e)` and says equality covers that interval, ordering uses only its start and sort keys use its start ([ledger:25-26](./decisions-ledger.md#L25-L26)). [H] These cannot be the same comparison operator: at `e`, ticket 19 says equal but L13 says not equal; at `s+12h`, L13 says both `Date == instant` and `Date < instant`. It would be incorrect to implement filter equality using `sort_key.cmp()==Equal`, or `<=` as `(< || ==)` under this contract.
- [H] A workable *predicate* interpretation for **instant `x` against interval literal `[s,e)`** is `==: s<=x<e`, `<: x<s`, `<=: x<e`, `>: x>=e`, `>=: x>=s`. The reversed-operand predicates must be derived by swapping sides, not copied verbatim. Even these interval predicates are not an `Eq` or `Ord`: a day equals both 09:00 and 17:00 although those instants do not equal one another. For period versus period, overlap, containment, and identical bounds are three different relations: month July overlaps the ISO week 2026-W31, and a July 29 day lies within both ([prototype `relate`:177-193](/tmp/period-proto/src/lib.rs#L177-L193), [cases:107-139](/tmp/period-proto/tests/table.rs#L107-L139)). **Do not use interval containment as grouping/hash identity, deduplication, or sort-comparator equality.**
- [H] The `/tmp/period-proto` citations document the unmerged scratch implementation inspected, not independent authority: interval rules derive from L13's half-open contract ([ledger:25-26](./decisions-ledger.md#L25-L26)), and ISO-week properties have a [first-party Jiff reference](https://docs.rs/jiff/latest/jiff/civil/struct.ISOWeekDate.html).
- [H] If L13's "ordering compares against the day's start" means `Date(D) < instant(D, noon)` while interval equality also returns true, it is internally inconsistent with normal ordering operators, not just Rust's `Ord`. Even if ordering treats every instant inside the day as equivalent, transitivity fails: `Date(D) ~ 09:00`, `Date(D) ~ 17:00`, but `09:00 < 17:00`. Keep the interval relation strictly inside filter predicates; give sort a **separate deterministic total key** `(first_instant, kind/precision, stable tiebreak)` and keep `NoteFieldValue: PartialEq` structural. A start-only sort key is a preorder with ties between different values, not a total order by itself. [V] This three-relation separation was already the point of [ticket 19:72-87](../../issues/19-coercion-and-comparison-policy.md#L72-L87); Jiff explicitly explains its `Zoned` Eq/Ord compare only instants because those trait implementations must agree ([primary Jiff docs](https://docs.rs/jiff/latest/jiff/struct.Zoned.html#comparisons)).
- [V] The compiled ctx-lab **does not model L13**: `to_instant(Date)` calls `promote_in` for midnight and `compare_in` compares two promoted instants ([ctx-lab `temporal.rs`:90-120](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L90-L120)); its `day_interval_in` is independent ([same:43-70](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L43-L70)). [H] Passing that lab's tests does not establish L13 equality, endpoint predicates, total sort, or result-set error propagation. [V] Its `Resolved` stores one `Arc<Calendar>` at the root, not on "only the few temporal nodes" as L4 says ([ctx-lab `plan.rs`:12-47](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/plan.rs#L12-L47)). [H] One capability per resolved plan could actually be leaner than cloning/storing one Arc per node, provided the evaluator exposes calendar operations only at temporal branches; distinguish the safety requirement (no clock access) from a prescriptive field placement.

## L4, L5, L12: resolve, frames, and lazy sets

- [V] Existing `QueryService::run` accepts no evaluation input and returns a `QuerySet`; it executes the builder's initial plan before returning (`src/query/service.rs:102-114`), whereas further `QuerySet` transforms queue a plan (`src/query/results.rs:456-490,520-540`). [V] `QuerySet::rows` has an infallible `&Arc<Vec<QueryRow>>` return and memoizes a **non-Result** with `OnceLock`; `len`, `get`, `iter`, `format`, `PartialEq`, `Debug`, and both `IntoIterator` forms force it (`src/query/results.rs:479-518,698-760`). [V] `QueryTransform::apply` returns `Vec`, calls boolean `FilterExpr::is_matching`, and uses an infallible sort comparator (`src/query/plan.rs:238-249,279-318`; `src/query/grammar/filter.rs:213-225`). [H] A genuine typed *per-row* zone error (L6) is not a local `Calendar` substitution: either materialization becomes fallible throughout the public set, iterator/format, template sequence and CLI call chain, or it is hidden/dropped/panics. Since empty or civil-only dynamic rows must succeed without zone under L6, conservative bind-time resolution of every potentially mixed comparison is not an equivalent workaround. This is the highest-priority missing seam decision for [ticket 26](../../issues/26-query-core-and-plan.md#L9-L18), not merely a plumbing detail.
- [H] Counterexample: query `due == "2026-07-29"` over a `due: Date` row and a `due: Instant` row, with system-zone discovery unavailable. Its first row can be civil-only, but the instant row needs a zone. `resolve` cannot decide the row's kind statically because fields are dynamically typed ([ticket 19:113-121](../../issues/19-coercion-and-comparison-policy.md#L113-L121)); `query.from(...).filter(...).count()` currently returns an infallible count ([`QuerySet::len`:493-504](../../../../src/query/results.rs#L493-L504), [`QuerySet::call_method` count docs:321-352](../../../../src/template/engine/query.rs#L321-L352)). [H] Preferred contract if L6's typed error survives: own it in the query execution/result-set module, expose a **fallible materialization boundary** and decide whether sequence iteration is fallible or materialized before a minijinja object is returned. An eager check of all potentially affected rows at `run_with` is another honest option but changes laziness and duplicates work when transforms select a subset. Strongest dissent: retain infallible row evaluation, make zone-unavailable a well-defined null/non-match plus a *visible diagnostic* collected by execution; this preserves lazy APIs but weakens L6's typed-error promise and ticket 19's "filters never error" remains coherent ([ticket 19:159-167](../../issues/19-coercion-and-comparison-policy.md#L159-L167)). **Flip fact:** whether consumers require typed per-row failure, rather than diagnostics/unknown, strongly enough to break the infallible QuerySet interface.
- [V] ctx-lab `resolve` folds `Today`, constant `AddDays`, and `StartOfWeek` and returns a bound plan ([`resolve.rs`:11-36](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/resolve.rs#L11-L36)); its evaluator has no `Frame`/clock parameter ([`plan.rs`:30-55](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/plan.rs#L30-L55)). [H] This is a sound direction for L4 **if** resolver handles typed literal candidates and *all* places relative terms occur (comparison operands, `date()`, `date_add`, arithmetic, template-built expressions), and leaves a zone-only calendar in row-dependent mixed operations; [ticket 19:107-134](../../issues/19-coercion-and-comparison-policy.md#L107-L134) requires adaptive candidates. A `today` literal is a civil date requiring the zone to compute *today* at resolution; a bare fixed date needs no zone. [V] Spark and DataFusion make `current time` statement-stable by folding it at analysis/simplification, but their typed columns allow earlier decisions Traces' dynamic rows do not ([first-party source URLs in precedent:9-15,40-50](./r3-engine-coupling-precedent.md#L9-L15)). [H] The strongest dissent is the opaque per-query `Frame` restricted to temporal operations: less AST duplication and easier extension to arbitrary dynamic filter functions; its testable weakness is giving every expression access to time and obscuring which nodes are stable. **Flip fact:** measure the real grammar's temporal node expansion, allocation/copying, and semantic reach—not the lab's six-variant expression ([brief-r3:135-146](./brief-r3.md#L135-L146)).
- [H] L5 and L12 need **two distinct lifetimes**: a reusable service owns a *source of frames* (not a frozen frame), whereas each `run`/`run_with` samples **one** frame to resolve an AST; a template-scoped source must give that **same `Arc<Frame>`** to every nested query/set. Any `QuerySet` escaping the render either captures its creator's frame (and may be intentionally stale later) or must carry the unresolved AST and an explicit `refresh`/rerun rule; it must not silently sample the current reader's frame on first materialization. [V] `push` currently replaces the set cache and keeps only `base`+`plan` (`src/query/results.rs:520-529`); the lab distinguishes unresolved `Expr` and stale `Resolved` ([`resolve.rs`:30-36](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/resolve.rs#L30-L36)). [H] Midnight refresh in L5 must include **plan re-resolution and cache invalidation**, not merely rerendering an already memoized `QuerySet`; a request crossing local midnight remains coherent to its original sample. For a system-local zone whose rules/name change while a process runs, "pinned" means the frame's zone, not host-global immortal zone. Strongest dissent: pin frame at workspace open and replace workspace object on every midnight; simpler executor but stale detached lazy sets. **Flip fact:** whether a result set can survive across requests/renders in the committed LSP/MCP interface. [V] L5 explicitly delegates diagnostic refresh scheduling to the host ([ledger:18](./decisions-ledger.md#L18)).

## L6: skipped days, zone failure, and formatting

- [V] Jiff documents a midnight gap producing 01:00 in `America/Sao_Paulo` on 2015-10-18, and `Zoned::start_of_day()` returns the first instant, not necessarily midnight ([Jiff Zoned docs](https://docs.rs/jiff/latest/jiff/struct.Zoned.html)). [V] Both prototypes implement day bounds using `date.to_zoned(zone).start_of_day()` plus a civil-date equality check ([ctx-lab `temporal.rs`:43-70](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L43-L70); [`period-proto`:142-164](/tmp/period-proto/src/lib.rs#L142-L164)). [H] They both wrongly reject a perfectly valid 2011-12-29 in `Pacific/Apia`: its end label `2011-12-30` is completely skipped, so computing `first_instant(end)` yields `SkippedDay`, despite Dec 29 containing instants. The next actual boundary, the first instant of Dec 31, should be the exclusive end of Dec 29. For Dec 30 itself, possible policy is empty `[s,s)` vs typed `SkippedDay`; document it separately, never let the end of a valid preceding day inherit an error. **Flip fact:** whether a skipped-date literal is contractually an invalid value rather than an empty period (both can retain correct Dec29 bounds if boundary calculation distinguishes nonexistence from end-exclusive).
- [H] The skipped-next-day counterexample follows from the checked endpoint algorithm in the **repo** lab ([ctx-lab `temporal.rs`:51-70](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L51-L70)) together with Jiff's documented compatible resolution of zone gaps ([Jiff Zoned docs](https://docs.rs/jiff/latest/jiff/struct.Zoned.html)); the `/tmp` prototype is supplemental, not product evidence.
- [H] For multiple consecutive skipped dates or extreme representable endpoints, use "first representable instant whose *local date is >= boundary civil date*" as the endpoint definition, rather than requiring that boundary date itself occur. Check potential non-monotone historical date changes and checked calendar overflow separately; do not subtract a nanosecond for an inclusive end. The preliminary `period-proto` is not product code and its test checks only skipped Dec30, **not Dec29** ([tests:163-180](/tmp/period-proto/tests/table.rs#L163-L180)); no execution proof of this corrected algorithm is claimed.
- [H] This end-exclusive rule is an interpretation of L13's interval semantics ([ledger:25-26](./decisions-ledger.md#L25-L26)) and Jiff's zone ambiguity contract ([Jiff Zoned docs](https://docs.rs/jiff/latest/jiff/struct.Zoned.html)), not an observed production implementation.
- [V] Current `DateTimeValue::Display` resolves ambient local zone and maps failure to `fmt::Error` (`src/temporal/datetime.rs:293-306`), whereas `Serialize` explicitly uses UTC without zone lookup (`src/temporal/datetime.rs:357-371`). `NoteFieldValueRef::append_text` ignores the `write!` failure, including the DateTime arm (`src/note/field.rs:315-339`); query rendering delegates there (`src/query/value.rs:53-69`). Template `field_value` calls `DateTimeValue::to_string()` (`src/template/engine/query.rs:594-603`). [H] On failed local-zone lookup, text tables/list output can silently omit the datetime (or show a partial field), while template conversion can fail in formatting rather than deliver a typed temporal error; Rust's `fmt::Write` docs say formatter errors are for destination failure, not a vehicle for time-zone lookup diagnostics ([Rust primary docs](https://doc.rust-lang.org/std/fmt/trait.Write.html#errors)). L6 must cover **formatting/display and template conversion** as well as comparison; render with the frame's zone explicitly and propagate `Result`, or choose an unambiguous invariant UTC representation for generic `Display` and reserve local rendering for explicit fallible methods. Strongest dissent: keep the ambient display as a convenience outside the query core; its observable failure is precisely the above silent formatting path. **Flip fact:** whether CLI stdout DateTime spelling is fixed by the frozen stdout-shape envelope ([ledger:33-39](./decisions-ledger.md#L33-L39)); this constrains adapter rendering, not the ownership of zone lookup.
- [H] **L6 policy options:** (a) system-local, pinned per frame, typed failure only on a genuinely zone-dependent operation (the ledger's preference); (b) an explicit UTC default selected by the host, for unattended deployments; (c) warn and silently reinterpret local dates as UTC, which changes query truth and must be rejected. [V] The current code hides failures both in filtering (`local_zone().ok()?` in `src/query/grammar/filter.rs:375-415`) and sorting (`src/query/sort.rs:369-397`); the ledger explicitly forbids dropping rows or treating `Etc/Unknown` as UTC ([ledger:19](./decisions-ledger.md#L19)). [H] Option (b) is the strongest dissent if the host cannot supply a system zone: make UTC an **explicit host policy**, never a quiet fallback inside `Calendar`. **Flip fact:** an operational requirement for unattended hosts with no discoverable zone and no configured zone. A zone-free pure-civil comparison should not force zone discovery (ctx-lab civil arms [`temporal.rs`:110-117](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L110-L117)); per-row conditional failure still requires the fallible query interface above.

## L7-L9: precision, week labels, filename parsing

- [V] `FileMeta::derive_day` currently reads day/month prefix and drops its precision with `.date()`, otherwise falls back to `created_at` converted to local date (`src/file.rs:86-98`); the prefix lexer supports only day/month (`src/temporal/lexer.rs:16-26`). [H] L7's filename-only precision value should be a *civil period* or written precision plus start, not just a `DateValue`: month, quarter, year, and week can overlap, and a week-year is not necessarily the calendar year of its first day. E.g. ISO `2026-W01` starts `2025-12-29` ([prototype:37-42](/tmp/period-proto/tests/table.rs#L37-L42)). Persisting `(kind,start)` is zone-free, but formatting the original week label from it requires the exact numbering rule or original lexeme; changing `DateConfig` can therefore require index invalidation or query-time reparse, as already noted in [brief-r3:181-186](./brief-r3.md#L181-L186). Strongest dissent: persist the original matched lexeme and parse period lazily under current config, minimizing stale interpretation while costing per-row parsing. **Flip fact:** whether `DateConfig`'s custom prefix patterns can change independently without a guaranteed fingerprint/rebuild.
- [V] Jiff documents that ISO week years differ from Gregorian years and week one contains the first Thursday ([Jiff ISOWeekDate](https://docs.rs/jiff/latest/jiff/civil/struct.ISOWeekDate.html)); the repo's own DateConfig handoff recognizes the need for an index fingerprint or query-time reparse ([brief-r3:181-186](./brief-r3.md#L181-L186)). `/tmp` examples remain supplemental.
- [H] L8's future "first weekday" alone does not define week-year numbering: the week containing Jan 1 may belong to prior/new year depending on the **minimum days in week 1**, e.g. Sunday-first/one-day gives 2026-W01 start 2025-12-28, Sunday-first/four-day gives start 2026-01-04 ([prototype:45-53](/tmp/period-proto/tests/table.rs#L45-L53)). ISO `2025-W53` is invalid while `2026-W53` exists ([prototype:54-59](/tmp/period-proto/tests/table.rs#L54-L59)); accept no rollover on an invalid week. Strongest dissent: freeze ISO week-year interpretation for `YYYY-WWW` regardless of configurable week start, let `start_of_week()` use config; this avoids dynamic prefix ambiguity but makes one "week" word mean two rules. **Flip fact:** a product example specifying non-ISO week-labeled filenames with expected year-boundary dates. [V] The current lexer has no standalone year, week or quarter prefix ([`lexer.rs`:16-26](../../../../src/temporal/lexer.rs#L16-L26)), so the prototype's interpretation of a book named `1984` as a year and its refusal of compact `20260729` are *proposed* choices, not observations of current behavior ([prototype tests:72-104](/tmp/period-proto/tests/table.rs#L72-L104)). [H] Demand an explicit prefix boundary/filename ambiguity policy and make raw dates vs configured patterns precedence deterministic; do not silently make every four-digit basename a year note.
- [V] ISO requires **both** a Monday start and a first-Thursday/four-day week-one rule ([Jiff ISOWeekDate](https://docs.rs/jiff/latest/jiff/civil/struct.ISOWeekDate.html)); the ledger fixes Monday for the default but allows future week-start customization ([ledger:20-21](./decisions-ledger.md#L20-L21)). [H] Sunday-first example dates and year-boundary behavior are deductions under the alternative min-days parameters, not current production behavior; `/tmp` examples are supplemental.
- [V] Today `file.cdate` falls back to **modification time** when filesystem `created_at()` is unavailable and produces a *local civil date*, not a raw instant (`src/query/results.rs:271-289`); `file.date`/`file.day` returns `Null` when no prefix if L9 removes fallback (`src/query/results.rs:307-312`; `src/file.rs:86-98`). [H] Therefore the shorthand `file.date ?? file.cdate` does not literally preserve the old fallback on all platforms unless its now/zone resolution is pinned and callers accept the existing mtime fallback semantics. L9 is sound as an explicit separation of filename period from filesystem-derived date, but must be reflected in templates, filter adaptation, and sort keys: `file.date` has precision and `file.cdate` is day precision. Strongest dissent: keep a separate `file.date_or_created` convenience field to preserve a common query; it risks recombining incomparable provenance and hiding the no-prefix case. **Flip fact:** an actual saved-query compatibility envelope requiring `file.day`'s fallback on no-prefix files, as opposed to only preserving CLI output shape ([ledger:33-39](./decisions-ledger.md#L33-L39)).

## L13 and L18: explicit ownership across query and template

- [H] Preferred placement: temporal owns checked civil period construction, date/instant boundary mapping and formatting with an explicit zone; value-semantics owns filter interval predicates **separately** from its sort-key relation; query resolve folds relative literals and attaches a zone-only capability to row-dependent operations; query result-set owns fallibility/lazy memoization; template adapter owns render-scoped frame sharing and output error mapping. [V] This aligns with [ticket 19's ownership list](../../issues/19-coercion-and-comparison-policy.md#L169-L178), [ticket 26's lazy set](../../issues/26-query-core-and-plan.md#L9-L18), and [ticket 28's typed minijinja bridge question](../../issues/28-template-engine-boundary.md#L9-L18). Strongest dissent: use uniform point promotion to midnight for **all** comparisons; that gives an actual order and cheap sort with no interval predicate, but deliberately discards L13 whole-day equality and ticket 19's coarse-literal semantics. **Flip fact:** a concrete user-visible day-vs-instant equality expectation (e.g. `due == 2026-07-29` when `due` has 18:00 offset).
- [V] Template currently registers date helpers as free functions/namespace closures with ambient `Timestamp::now` in `Anchor::base` and `is_past`/`is_future` (`src/template/engine/date.rs:158-172,265-275,1006-1027`), plus local-zone reads in date arithmetic (`date.rs:112-135`). A render starts with `render_captured(minijinja::context!())` (`src/template/engine.rs:170-203`), and query callbacks have `&mut State` for render-local caching (`src/template/engine/query.rs:195-234,237-249`). An existing typed-extension `cached<T,E>` stores shared cheap-clone values by `TypeId`, reused across includes/blocks/macros, but **does not cache failures**, and two call sites with the same `T` share a slot (`src/template/engine/cache.rs:1-55`). [H] A lazily cached `Arc<Frame>` through that extension is the smaller existing seam than adding an invisible root-context key; add State access to `shorthand`, filters/tests, and nested queries, and define initial sampling as first temporal use rather than arbitrary render entry **unless** L5 requires exact render-entry instant. Alternatively sample once at render entry and insert an opaque context carrier; this meets exact entry-time semantics but needs propagation through `{% import %}`, includes, caller-provided variables and non-template query paths. Strongest dissent: hidden root key (ctx-lab reports an include/import probe at [brief-r3:89-98](./brief-r3.md#L89-L98)), with the advantage of an explicit entry sample and less closure capture, but more coupling to minijinja lookup visibility. **Flip fact:** prove real `date.*`, `{% include %}`, isolated `{% import %}` and query callbacks all see one frame under the selected minijinja mechanism; the mini lab is not the real engine.
- [H] Important lifecycle counterexample for L18: `set q = query.from(...).filter('due == today')` in a render at 23:59 and `q.count()` at 00:01 must still use **one sampled render frame**; a lazy set resolving at count time from an engine-global clock would drift. If a query set is stored and consumed after render completion, even a render-local State extension no longer exists, so attach the `Arc<Frame>`/resolved plan to the set at construction. [V] The current `QuerySet` `Object` implementation reads via its own `get` and `len` without `State`, while method dispatch receives a `State` argument but ignores it (`src/template/engine/query.rs:305-320,358-375`). [H] A state-only carrier at terminal access cannot enforce L18 on sequence iteration; frame capture is the simplest coherent design. Template comparisons are also currently converted to minijinja scalar values/strings (`src/template/engine/query.rs:586-611`); the [ticket 28 handoff](../../issues/28-template-engine-boundary.md#L39-L45) requiring shared value semantics is not established by merely sharing a frame. **Flip fact:** a verified typed minijinja adapter that routes all comparisons and formatting through the value-semantics relation without eager stringification.

## What reading alone does **not** establish

- [H] No claim here of running code, tests, or benchmarks. The supplied mini-labs and existing tests only show the cases they explicitly cover ([ctx-lab `temporal.rs`:43-120](../../../../.design/2026-10-22-review-ambient-execution-context/models/ctx-lab/src/temporal.rs#L43-L120); [`period-proto` test cases](/tmp/period-proto/tests/table.rs#L142-L180)); they do **not** prove production date comparison, skipped-next-day handling, zone-failure propagation, minijinja import/state behavior, per-row cost, or date-prefix config invalidation.
- [H] `/tmp/period-proto` is outside the repository and only illustrates hypotheses; the authoritative product contracts being tested are [ledger:17-26](./decisions-ledger.md#L17-L26) and [ticket 19:94-130](../../issues/19-coercion-and-comparison-policy.md#L94-L130).
- [H] Whether the local zone can be unavailable on each supported host; whether external saved queries rely on the old no-prefix `file.day` fallback, ambiguous four-digit titles, or an inclusive interval end; how many held LSP/MCP sets survive requests; and whether minijinja typed values can intercept every native comparison are not established from the consulted repository code and notes. Each is a **flip fact**, not a reason to quietly approve L4-L9/L12-L13/L18.

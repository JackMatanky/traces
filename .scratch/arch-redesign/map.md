# Traces architectural redesign — decision map

## Destination

Reach an evidence-backed, internally coherent body of architectural decisions sufficient to derive a **comprehensive redesign specification for Traces**: component and crate boundaries; ownership and enforcement of significant invariants; what is decomposed, consolidated, redesigned, introduced, or eliminated; improved domain models, interfaces, and abstractions; changes to dependencies, data flows, algorithms, and data structures; the tradeoffs behind each; and the dependencies/constraints that govern implementation. The map is complete only after a cross-decision reconciliation (see *Not yet specified*), not merely when every ticket is closed.

This is a **planning-only** effort (Wayfinder default): no production code, tests, or benches are modified. When the map is resolved, hand off to the specification stage; do not implement.

## Notes

**Origin**: whole-codebase recursive architectural deepening and redesign brief (invariant ownership, domain modeling, architecture + algorithms; evaluation criteria: invariant ownership/correctness, cohesion, depth of abstraction, coupling, conceptual simplicity, composability, maintainability, flexibility, algorithmic/resource efficiency, testability/risk). The criteria are not a scoring system; file count, LOC, and number of abstractions are never quality measures. The existing design is an implementation to investigate, not a design to preserve — and equally, a design that withstands adversarial scrutiny is to be kept.

**Domain**: read `GLOSSARY-MAP.md` and the per-module `src/*/GLOSSARY.md` files before any ticket touching that module's terms. Glossaries, ADRs (`docs/adr/0001`–`0009`), comments, and the earlier `.design/` temporal reviews are *claims to check*, not evidence. Known drift is listed in the surveys (e.g. `src/GLOSSARY.md` defines `Occurrence`/`NavTarget`/`Resolution` that do not exist in code). ADR-0009 (index refresh) is the decided direction of in-flight work (see *In-flight implementation baseline*), not drift.

**Skills**: every grilling ticket invokes `/grilling` and `/domain-modeling`. Type/ownership questions also consult `/rust-design` (Model mode: parse-don't-validate, typestate only where states are stable, concrete before generic) and `/rust-skills` once a concept is discovered. Research tickets are resolved by a `/research` subagent. Use `codegraph` for call/impact tracing, and `rust-docs-mcp` (current crate versions) for crate API questions; consult the ecosystem separately from the source ("what does the API demand" vs "what does the ecosystem reach for"), never letting one stand in for the other.

**Evidence tiers.** Every ticket answer MUST keep these apart: *verified finding* (cites `file:line` and was re-checked), *hypothesis* (falsifiable, unresolved), *alternative* (design option), *decision* (closed), *post-Wayfinder implementation work* (never a ticket). The ten **surveys** in [survey/](survey/) are subagent-written single-pass reports; the verification ledgers ([Verify core findings](research/01-verify-core-findings.md), [Verify system findings](research/02-verify-system-findings.md)) refuted several of their claims (e.g. `CliError` has 22 variants not 52+; there is no six-layer error chain; chained `QuerySet` calls clone an `Arc`, not rows; `TestProject` is 266 lines; `src/cli/query.rs`/`schema.rs` do not exist; `strsim`/`yaml`/`env_vars`/`hash` are not single-consumer; the note GLOSSARY's slug-dedup/footnote/callout claims have no code). **Decision tickets cite the ledgers and the [performance evidence](research/03-performance-evidence.md), never the surveys alone; a survey claim absent from a ledger is a hypothesis.**

Surveys: [root primitives](survey/root-primitives.md) · [note](survey/note.md) · [index](survey/index.md) · [query](survey/query.md) · [schema](survey/schema.md) · [template](survey/template.md) · [config/trust](survey/config-trust.md) · [cli/dialog](survey/cli-dialog.md) · [temporal](survey/temporal.md) · [cross-cutting](survey/cross-cutting.md).

**Research-ticket output convention** (matches `md-pkm-lsp`, whose precedent this repo's local tracker follows): findings go to `.scratch/arch-redesign/research/<NN>-<slug>.md` and are linked from the ticket's `## Answer`; no git branch is created.

**In-flight implementation baseline (user priority, 2026-10-18).** The maintainer is implementing [config-service/07 — per-section config digests](../config-service/issues/07-config-digest-sections.md) (WIP in worktree `.worktrees/config-digest-sections`), to be followed by [index-query/17 — config drift detection and rebuild](../index-query/issues/17-config-drift-detection-and-rebuild.md) (ADR-0009). Treat both as **decided and landing**, not as open questions and not as defects: the target architecture MUST assume them landed. Settled by them: `Config::digests()` returns framed per-setting digest bundles built by exhaustive (`..`-free) destructuring so a new setting fails closed; `Config::hash()` becomes compose-all under `b"traces.config.v1"`; `FieldName::feed_into` owns the "exact UTF-8 bytes" contract and the dependency direction is `field → hash`; the **index owns all invalidation policy** (`IndexFingerprint`, `IndexSetting`) and consumes `ConfigDigests`, dependency direction `index → config` only; the redb store gains a `meta` table written in the same transaction as the index rows and a legacy store is wiped at open; refresh gains `Drifted` (drift wins over staleness; a missing/undecodable meta row in a populated store is drift, fail-closed); `RefreshReport` becomes `Unchanged | FilesChanged{..} | ConfigDrift{changed}`. Consequences for this map: (a) claims about "single undifferentiated `Config::hash()`", "no drift detection", and the exact redb table set describe `main` before config-service/07 and index-query/17 land, and are tagged `MOVING (07/17)` (the tag means those two in-flight tickets) in the verification ledgers; (b) [Config ownership](issues/13-config-ownership-and-lifecycle.md) and [Index read model](issues/15-index-read-model.md) may identify tensions between the forward architecture and 07/17 but cannot silently overturn them — an apparent conflict is recorded as an *amendment candidate* for the maintainer; (c) the exhaustive-destructuring digest convention constrains where config section types can live (see [Config ownership](issues/13-config-ownership-and-lifecycle.md)).

**Standing constraints** (apply to every ticket):

- Preserve existing capabilities and observable CLI behavior (process contract: stdout results / stderr diagnostics, exit codes 0/1/2/130) unless a decision explicitly justifies the change.
- No performance regression without an explicit, evidenced tradeoff; performance claims need measurements ([Performance evidence](issues/03-research-performance-evidence.md)) or are flagged `[INFERENCE]`.
- The core is currently **synchronous** (rayon for data parallelism; no async runtime). Whether that stays is a live question only where a ticket's evidence demands it; the `md-pkm-lsp` map already scoped any async runtime to the transport edge.
- Workspace trust / root-confinement security invariants (ADR-0002, `SafeRelativePath`, atomic `CreateNew` writes) must be preserved or strengthened.

**Cross-effort input — the planned Markdown/PKM language server** ([md-pkm-lsp map](../md-pkm-lsp/map.md)) is a *driver and constraint*, not the destination: the redesign must make that work coherent (spans on the note model, live-buffer overlay, swap-on-refresh snapshot host, protocol-free navigation spine, static template analysis, schema validator, per-section config digests) but its feature/product decisions stay owned by that map. Where a redesign decision contradicts a settled LSP-map decision, record the conflict in the ticket's answer and flag the LSP ticket for amendment (as md-pkm-lsp tickets 25/26 did for md-pkm-lsp ticket 11 §8) rather than silently diverging.

**Precedent research caveat.** The precedent files (the five precedent research tickets) were asked for lessons only, but several lessons end with an "Application:" line that reads like a recommendation for Traces (for example, "[Note document model](issues/14-note-document-model.md) must split the syntax model from the persisted summary"). Treat every such line as a **hypothesis to grill, not a decision**; the decision tickets own the verdict. Lessons are also weighed against Traces' measured constraints ([performance evidence](research/03-performance-evidence.md)) and against in-flight work. Precedent from large tools (workspace granularity, multi-crate test crates, planner machinery) is admissible only where its transferability test holds. Note: the precedent files cite minijinja 3.0 facts, whereas `Cargo.toml` pins `minijinja 2.24.0`; [Carry-forward evidence gaps](issues/21-research-carry-forward-evidence-gaps.md) checked them (`undeclared_variables` exists in 2.24.0; `get_or_insert_extension` is 3.0-only), so rely on that ledger rather than on the precedent file.

**Provisional keep-as-is hypotheses** (survey verdicts, *not* decisions; re-test adversarially only if a ticket's decision touches them, and carry the verdict into the spec otherwise): `DatePoint` / temporal value model (production ~500 SLoC; file size is tests); `InlinkMap` flat-scan/trie hybrid; `FilePathTracker` as a platform-resilient primitive; schema CSR graph + Kahn linearization; `DialogProvider` four-primitive trait shape; `RelativePath`/`SafeRelativePath` split; infallible `parse_markdown`; flat document-order `ListItem` slice.

## Decisions so far

- [Research: verify value/note/schema/config/temporal findings](issues/01-research-verify-core-findings.md) — all eight claim groups checked against `main` `0c43149d`: six verified; the parse pipeline and the root-primitive census partial (errata: `delimiter` and `lexer` are multi-consumer). Key facts: `note → config` and `index → config` are each a single edge; the value chain `noyalib::Value → FieldValueRef → NoteFieldValue` is real and `DateTimeCoercion::Classify` fires in exactly one production place; `QuerySet` has no zone and 24 `local_zone()` sites exist; `schema` has zero `note` references, no note-vs-schema validator exists, `SchemaDateField.format` is dead; of `frontmatter` settings only `tags_name()` is read in production; note GLOSSARY slug/footnote/callout claims are refuted. [Ledger](research/01-verify-core-findings.md).
- [Research: verify index/query/template/cli/topology findings](issues/02-research-verify-system-findings.md) — four verified, four partial. Key facts: `IndexStore` has seven responsibility clusters and `main` has 8 redb tables (no `lists`); the CLI uses only `run_from_store` and templates only `run`, with shared row/plan code and identical results; `QueryRow` is 48 B and `cmp_document_order` has an unpinned defect (ignores list-item index); `TemplateEngine::new` is a second composition root (builds `SchemaService`, `IndexerService`, three `QueryService`s); `CliError` has 22 variants and the crate 42 error types; production module graph is a strict DAG; `traces::testing` is exactly 45 identifiers; only `Note` and `FileMeta` are redb payloads and nothing guards the format beyond `cache_format = "1"`. [Ledger](research/02-verify-system-findings.md).
- [Research: performance evidence for read-model decisions](issues/03-research-performance-evidence.md) — fixed floors dominate the CLI: redb commit ≈ 36.8 ms, redb open+read ≈ 16 ms, process ≈ 4.5 ms; in-memory `run` is µs (3.9 µs @1K, 75 µs @20K) while store-backed single-match queries cost 16–71 ms and 21 MB at 20K; at 20K notes the selective-query floor is the directory scan + `stat` (~40–45 ms); note parsing is ~5–8% of a cold build (second heading pass unseparated); sort precomputes keys (no ambient-zone cost in the compare loop) while date filters that evaluate calendar arithmetic (`eom`, offsets) pay ambient `local_zone()` lookups per row (0.8 ms for a plain date filter vs 2.2–2.7 ms with arithmetic, @20K). Consequence: an in-memory inverted index to speed CLI queries is unsupported by the data. [Evidence](research/03-performance-evidence.md).
- [Research: precedent for dynamic values, coercion, and schema validation](issues/04-research-values-coercion-validation-precedent.md) — eight graded lessons from SQLite, Polars/DuckDB, `serde_json`, `jsonschema`, Dataview, Metadata Menu, rumdl: coercion at ingestion rather than query-time re-sniffing, explicit type-rank ordering, lossless 64-bit integer identity, schema as interpretive/diagnostic overlay rather than an ingestion gate. [Lessons](research/04-values-coercion-validation-precedent.md).
- [Research: precedent for execution context, configuration ownership, and composition roots](issues/05-research-context-config-composition-precedent.md) — eight lessons from cargo, ruff, gitoxide, jj, jiff, ripgrep, rumdl, Templater: explicit `(now, zone)`/context threading vs ambient statics, domain-owned settings, immutable `Arc` snapshot handles for a host, and negative lessons on leaking host instances into template engines and on ambient cwd. [Lessons](research/05-context-config-composition-precedent.md).
- [Research: precedent for syntax vs persisted summary, caches, and freshness](issues/06-research-document-summary-cache-freshness-precedent.md) — comparables (rustc, rumdl, Dataview, Tasks) persist derived summaries, never syntax trees; mtime+size freshness is the classic racy-timestamp hazard (git/cargo/Mercurial mitigations; ruff/rumdl key on content hash + config); in-memory inverted maps with disk only as warm cache is the common query shape. [Lessons](research/06-document-summary-cache-freshness-precedent.md).
- [Research: precedent for query IR and template/capability boundaries](issues/07-research-query-ir-template-boundary-precedent.md) — eight lessons from DataFusion, Polars, jaq, gitoxide, minijinja, cargo-generate, Copier, Cookiecutter, Dataview, Templater, Tasks: one expression algebra can serve pruning and row filtering, result rows should not hold the engine, template engines resolve declared parameters up front (mid-render prompts are Templater-style), minijinja provides `State` extensions (3.0 only) and undeclared-variable analysis (also in the pinned 2.24.0). [Lessons](research/07-query-ir-template-boundary-precedent.md).
- [Research: precedent for diagnostics, error layering, and crate topology](issues/08-research-errors-crate-topology-precedent.md) — eight lessons from rustc, ruff, rumdl, cargo, uv, ripgrep, gitoxide: protocol-free diagnostics with byte-offset spans decoupled from terminal emitters, single package with `[lib]`+`[[bin]]` and no test side-door, negative lessons against `miette` derive on domain errors, string-erasing error layers, and over-fragmented workspaces. [Lessons](research/08-errors-crate-topology-precedent.md).
- [Research: carry-forward evidence gaps from the first research wave](issues/21-research-carry-forward-evidence-gaps.md) — `NoteFieldValueRef::compare` on a `Date`/`DateTime` pair calls the uncached ambient `local_zone()` on every comparison (reached from `<`/`>` filters and nested objects) and swallows a lookup failure into a fixed ordering (per-call cost unmeasured); pinned `minijinja 2.24.0` already has `undeclared_variables` but not `State::get_or_insert_extension` (3.0-only), and `machinery` needs `unstable_machinery` in both; the cost of a 3.0 bump is unchecked. [Ledger](research/21-carry-forward-evidence-gaps.md).
## Not yet specified

- **Schema internals** — scope of `fields/select.rs` (2K lines: inline/object/file TOML/JSON selectors), flattening the five-layer `schema::fields::error` hierarchy, typed-serde vs manual option parsing in `RawSchemaFieldDef`, and the `Schema` ↔ template `State` temp-storage hack. Graduates after *Schema and note typing* settles what a schema field type *is*.
- **Date-format dialect ownership** — Moment-token translation (`template/engine/date.rs`, 2.5K lines) vs `temporal`; the LSP daily-note `[periodic] format` and schema `date` `format` attribute are second consumers. Graduates after *Ambient environment* and *Template engine boundary*.
- **Query result presentation** — `table`/`list`/`task_list` rendering lives on `QuerySet` (`query/format.rs`), re-exposed as minijinja filters and driven by `cli/{table,list,task}.rs`; whether presentation is its own component, and whether CLI commands emit via a sink or return structured results. Graduates after *Query core* and *Template engine boundary*.
- **Lexing/parsing-engine consolidation** — `logos` (three separate lexers) + `winnow` + `speedate` + `pulldown-cmark`; shared `lexer.rs`/`delimiter.rs`/`position.rs` plumbing. Graduates after *Note document model*.
- **CLI query construction** — string-synthesized filters (`cli/task.rs`) and filesystem-probing `normalize_source_input`; typed query construction vs DSL strings. Graduates after *Query core*.
- **Test-harness design for the redesigned shape** — the shape of the fixtures and helpers themselves (the 669-line `test_support` module, of which `TestProject` is 266 lines) once the *access strategy* that replaces the 45-identifier `traces::testing` side-door has been decided in Crate topology (which owns the access strategy, not the harness internals). Graduates after *Crate topology*.
- **Cross-decision reconciliation** — before the map closes: contradictions between decisions, duplicated responsibilities that survived, newly introduced coupling, invariant conflicts, and a second recursive-deepening pass over boundaries a decision moved. Graduates into a ticket when the last decision ticket closes; closing the map requires it.

## Out of scope

- **Language-server feature and product design** — owned by [md-pkm-lsp](../md-pkm-lsp/map.md); only its architectural *demands on Traces* are in scope here.
- **Implementation sequencing, migration steps, and any production-code change** — belong to the specification stage after Wayfinder.
- **New user-facing features or DSL syntax changes** — only where an architectural decision strictly requires them, and then as an explicit tradeoff in that ticket.
- **Benchmark-infrastructure work** (criterion store, baselines) — a separate effort; this map only consumes existing measurements.

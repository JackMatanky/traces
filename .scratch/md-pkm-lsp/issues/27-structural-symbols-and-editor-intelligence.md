# Structural/editor intelligence: symbols, folding, selection ranges, document links, CodeLens, code actions, semantic tokens

Type: grilling
Status: resolved
Blocked by: 05, 15, 23
Assigned: agent

## Question

Grounded by the Microsoft markdown-language-service research (ticket 05) and the link model (ticket 15, for document-link ranges). **Caveat on ticket 05's evidentiary weight**: it is the map's *only* researched generic-Markdown-LSP precedent. No second implementation (e.g. a CommonMark-reference LSP, or a generic Markdown mode in a different editor's built-in tooling) was researched to cross-check it. Treat "even Microsoft's own implementation doesn't have semantic tokens/CodeLens" as one data point about one team's product choices, not as a normative ceiling on what Traces' generic-Markdown coverage should be. The destination asks for "the valuable generic Markdown language-service capabilities," decided on Traces' own users' needs, not for parity-with-a-cap against whichever single reference got researched first. Decide, for each, in/out-of-scope and depth:

- Document symbols / outline: heading hierarchy (this needs headings as first-class AST nodes; coordinate with ticket 11/15's decision to retain them) plus, optionally, task and File-Class-field structure.
- Folding ranges: heading sections, list nesting, code fences, callouts (if in scope per ticket 17), frontmatter block.
- Selection ranges: nested-selection expansion through list items, headings sections, inline spans.
- Document links (`textDocument/documentLink`): every resolvable link/embed target as a clickable range. Decide overlap/non-overlap with rumdl, which already provides file-path completion, but check ticket 03 for whether it also registers `documentLink` (if so, this needs the same coexistence-toggle treatment as link completion/navigation).
- Template references as document links (input pending from ticket 22): `{% include %}`/`{% extends %}` spans plus overlay-aware template-name existence. 22 derives both (its Q20(b) discovery seam). Decide at this ticket's resolution whether `documentLink` covers template references or leaves them to go-to-definition. This is deliberately *not* a `Blocked by: 22` edge (an optional input: 22 does not gate this ticket); re-evaluate the edge only if this Question gains a template-links scope item.
- CodeLens: reference-count lens above headings/notes ("3 references"), informed by whether Marksman/Markdown Oxide do this (tickets 01/02). Decide value vs cost (this needs backlink computation eagerly for every visible heading).
- Code actions beyond quick-fixes already covered elsewhere: e.g. "convert Markdown link to wikilink" or vice versa, "extract selection to new note".
- Semantic tokens: decide whether Traces defines any at all. Ground this against whether TextMate/tree-sitter grammar-based client-side highlighting already covers Markdown/wikilink syntax adequately (likely yes; semantic tokens add limited value for prose-heavy Markdown vs code) versus a specific case semantic tokens would uniquely enable (e.g. distinguishing a *resolved* vs *unresolved* wikilink by token type/modifier, which syntax highlighting alone cannot do).

## Answer

Resolved 2026-10-22 after a fully independent pass-2 re-research (a Phase-A substrate review (A1-A3), a Phase-B seven-cluster evidence pass, consolidation, and a 16-question grilling round with three questions held for Phase D, then Phase-D hardening: stress-test, benchmark, codegraph design-review, and ecosystem-convention subagents in parallel), and user confirmation of the locked set D1'-D16' ([research, Part XII](../research/27-structural-symbols-editor-intelligence-pass2.md); cluster reports in [research/27-pass2/](../research/27-pass2/)). The pass-2 file supersedes pass 1 on the seven conflicts it lists (Part X). Decisions:

1. **All nine capabilities IN, staged in three waves (d3 design-review inversion).** The parser already receives full byte spans from `into_offset_iter()` and discards the ends. The shared walk is an LSP-side free function `walk(src) -> DocStructure`, cached per `(uri, version)`, NOT a Note method and NOT merged into `collect_headings` (transient LSP spans must never enter the postcard-persisted Note, 11 §8). Wave 0 (prerequisites): the `[lsp]` config table + digest; a three-method LineIndex extension plus 26's convert wrapper; the already-budgeted `LinkResolver::resolve_link(from, raw) -> Option<PathBuf>` facade method (basename wikilinks). Wave 1 (ships BEFORE 11/14/26): all document-scope features (exact spans where the feature needs them; line-granular where the protocol is line-based). Wave 2 (named-ticket-gated): three-valued ambiguity (26), template-ref links (22), heading-level lens counts (26/38), overlay-fresh counts/tokens (14). **11 and 26 are NOT prerequisites** for 27's document-scope features (d3; corrections filed to 11 and 41).
2. **D1' Outline: headings + tasks as section children, Traces-original.** All five PKM peers emit headings only, but the convention is unexamined for tasks rather than rejected: a task is a definition with stable identity. Task children come from a single pass over `note.lists()` with an ancestor stack per 23's S3 pin (never `Note::tasks()` + depth), and still never QueryService (crate-split hazard, 34). Kind `Array` is separable via VS Code `outline.showArrays`, unlike `String` headings which collide with the built-in. Root/preamble tasks attach to a document-root pseudo-symbol; the section-end corner case is non-normative. Document truncation is logged at warn (not debug) at SYMBOL_CEILING (1k soft / 5k hard).
3. **D2' Folding E-lite + riders.** Heading sections, list nesting, code fences, frontmatter, callouts; runs on the raw walk (fences/frontmatter/list-ends/callouts leave no AST residue). Callout mapping: "foldable = NOT `+`". The `-` initially-collapsed state is inexpressible on the 0.23 lane and is dropped (client-side); an amendment is filed to 17 (`is_foldable` bool cannot carry Obsidian's three-state). `collapsedText` needs a typed-crate check.
4. **D3' Selection ranges: S1 IN.** Client-independent baseline; nested expansion through heading sections, list items, inline spans. Property test: every `positions[i]` lies within `ranges[i]`.
5. **D4' documentLink: Option A, exact spans, eager, resolveProvider:false.** Wikilinks, embeds, and standard links with exact walk spans (not line-granular). Check hrefRange overlap with the VS Code built-in at implementation. Emission is not 26-gated (only template refs are 22-gated, and dynamic template targets are dropped from emission); only the ambiguity tooltip joins Wave 2, gated on 26's tie-reporting candidates. Ambiguous links emit (see D6'); unresolved links are dropped (see D5'). No resolve phase: targets are computed eagerly via the Wave-0 facade.
6. **D5' Unresolved links: DROP, with the three-way handoff documented.** 25's diagnostic carries the default severity; 15's create-note quickfix rides the diagnostic lane; 26's informational hover is the residual. The silent-hole consequence must be documented, not silent: severity `off` + drop = no link, no diagnostic, no action, hover only.
7. **D6' Ambiguous links: first-candidate deterministic target + "N candidates" tooltip.** Documented graph-vs-nav divergence (the inlink graph keeps nearest-picks; navigation reports ties) and the Neovim limitation (`tooltipSupport = false` presents as an unconditional jump with zero signal). No per-client capability split in v1; revisit if nvim PKM users complain. Sign-off blocks are filed to 15 and 26; 26's "never error on ambiguity" pin stays untouched.
8. **D7' Semantic tokens: T1 legend, pins re-attached, two-valued Wave 1.** The `unresolved` modifier ships in Wave 1 (classified via `resolve_link` Some/None); the `ambiguous` modifier joins in Wave 2 with 26's candidates. Pins: never filter emitted tokens against client-advertised tokenTypes (that would delete the only wikilink color channel in VS Code); single-line non-overlapping (VS Code advertises multiline/overlap false); affirmatively do NOT advertise `full.delta` or `range`. The T2b modifier-theming fallback is unchanged.
9. **D8' Refresh is a server-to-client REQUEST, debounced, gated on refreshSupport.** `workspace/semanticTokens/refresh` and `workspace/codeLens/refresh` go through ONE shared "send refresh, swallow error" helper mirroring 25:24's diagnostic refresh (owed to 25/29). Each send is gated on the client's refreshSupport (Zed lacks folding refresh, so none is sent). Subscribe to 25 Q11-R's dirty/referrer snapshot-diff emission; no new transport lane; refresh is coalesced per kind: semantic tokens ≥100ms, CodeLens ≥250ms.
10. **D9' CodeLens: staged C→A, zero-reference suppression adopted.** Stage C counts come via binary-search `entries` + `FileEntry::inlinks().len()` (free suppression); Stage A heading counts wait on Wave 2. Pins: the used-flag = the client ever sent `textDocument/codeLens` this session; stale-`data` guard `{uri, range, version}` identity-on-stale; never a pre-serialized Location[]. Lens capability default false (client floor).
11. **D10' Code actions: four kinds with re-attached gates.** `refactor.convert.toWikilink`, `refactor.convert.toStandardLink`, `refactor.extract.note`, `refactor.rewrite.cycleStatus` (v1; `quickfix` joins with 25's action set, and kind advertisement is static). The `disabledSupport` capability gate applies (Helix absence accepted). 27 owns code-action-originated `CreateFile` emission plus the shared create-predicate (28 compatibility: any client-side create when 28 lands).
12. **D11' VS Code duplication: accept duplicates as default.** The lever set is ranked: accept (markdown-oxide practice); document the `outline.show*` filters honestly (all LANGUAGE_OVERRIDABLE; two `String` sources cannot be split by kind, so state the caveat); Traces-side per-feature config gates shaped like rumdl's `enableSymbols` for proven-duplicative capabilities; companion guidance (rumdl `enableSymbols = false` when Traces provides the outline); whole-extension disable as the heavy option only. Rejected: the SymbolKind dodge (zero precedent), Marksman-style identity-gating auto-cession (it deletes Traces' task outline). A file is filed to 32.
13. **D12' Freshness and asymmetry pins.** Workspace symbols reflect the last index refresh; overlay-authoritative only for document-scope features; the freshness window lasts until 14's RefreshPlan. Tags appear in the workspace picker but not the document outline: this is intentional asymmetry (16's hide-axis is an outline affordance). Corrected facts carried: rumdl and Marksman both register zero documentLink; Marksman nests tags in its outline (contradicting 16's pin; the 16 owner decides).
14. **D13' Corrected performance rows (final set for 33).** Doc symbols <10 target / <5 stretch headings-only, <10 / n-a with tasks (re-measured); workspace/symbol <50ms at the 10k tier, cap 128, derived per 33:117; folding 30/10 honoring client rangeLimit 5000; selection 10/5; documentLink ≤5 warm / ≤10 cold (UX-mandated, nvim gx is synchronous); CodeLens discovery 10/3, resolve 20/5; documentHighlight 10/3; semantic tokens 10/5. REFERENCE_CEILING becomes two-tier and clangd-shaped: a default soft cap of 1000 with visible truncation, plus a configurable hard ceiling of 5000 (this amends 26's named REFERENCE_CEILING constant: 26 pinned a flat 5,000 soft cap "fed to 27/29"; the two-tier model makes 5,000 the configurable hard ceiling and 1,000 the default soft cap). Vault-scale basis: 100 smoke / 1k typical-large / 10k power-user sustained / 50k stress-degradation-only + the 20k iwe cross-tool anchor. No Markdown PKM peer publishes per-request LSP latency: adopt an lsp-bench-shaped criterion suite (p50/p95 + RSS) before 33 accepts rows, and bench-report the equally unsupported 2MB@20k memory claim. A file is filed to 33.
15. **D14' Template refs: split gating.** Goto-definition over template refs ships when 22's resolution logic exists (not span-gated); documentLink emission waits on 22's exact spans (no line-granular underlines); existence is gated on 22's Q20(b) overlay set. Risk note: Traces ships minijinja 3.0.1 while 22 designs `machinery::parse` behind exact-pin `=2.24.0` (a dep mismatch carried into 22).
16. **D15' Outward record set: nine primary tickets plus sign-offs.** 23 (the eager-Location Section 6 amendment), 16 (tags precedent + PROPERTY kind for tag workspace symbols), 11 (the ropey method-name correction; 27 does not need 11's AST spans), 29 (capability fields for all nine + deliberate non-advertisement: workspaceSymbol/resolve, partialResultProvider, full.delta/range, documentLink/resolve, codeLens resolve until Wave 2), 33 (perf rows), 32 (duplication posture), 22 (Q24(b) restatement + minijinja risk), 41 (demand statement: transient spans only; 41-C is acceptable), 17 (the callout amendment), plus sign-off blocks to 15 and 26, and a runtime-toggle input to 31.
17. **D16' Capability lifecycle: static initialize-time gates + runtime-disable semantics.** ONE flat `[lsp]` table of per-feature `Option<bool>` (lens default false, rest default true), with the RawConfig/digest recipe (raw.rs:17, schemas.rs:127 precedent) and no nested sub-tables in v1. Initialize-time gates decide advertisement; runtime flips make handlers return empty results or method_not_found (framework default), sticky-until-restart per 22:65; the live-reload interaction is filed to 31. One convert seam (`char_to_utf16_cu(byte_to_char())` idiom) is shared by all nine handlers. No dynamic registration except file watchers (29 owns).
18. **Recorded consideration (user note, 2026-10-22): a possible Note-type split.** A separate arch-design wayfinder task may split the note type into an index/query-optimized variant and an editor-aware variant. This ticket's design is an early citizen of that split: `DocStructure` is the transient, span-rich, editor-scoped product of the walk and is deliberately NOT persisted or merged into the index-optimized Note (11 §8); the persistent Note stays index-optimized. This is carried as input to that future task, and no decision here depends on it.

## Inputs from 26 (2026-10-18)

- **documentLink emits for `Unique` and `Ambiguous` targets** (it never errors on ambiguity); semantic-token modifiers are **three-valued** (resolved / unresolved / ambiguous), not a boolean, per 26's `Resolution` enum.
- The spine exposes `highlight(target, doc)` for 16's tags and this ticket's documentHighlight registration; documentHighlight is document-local span matching and **never** errors on target ambiguity.
- The 5,000 references ceiling (26's named constant) is deliberately distinct from symbol-result ceilings; keep the two consciously distinct rather than unifying them.
- The create-note action's offering side must check `create` in `resourceOperations` (a shared predicate with 25's code-action path).

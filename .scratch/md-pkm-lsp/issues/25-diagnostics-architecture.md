## Question

Once link/reference resolution (ticket 15), schema validation (ticket 20), and query diagnostics (ticket 21) are each settled, decide the *unifying* diagnostics architecture:

- Decide aggregation: how per-feature diagnostic sources (unresolved links, ambiguous headings, schema violations, malformed queries, malformed templates) merge into one `textDocument/publishDiagnostics` payload per document. Decide the severity levels and the diagnostic-code namespacing. A client or user can distinguish a Traces diagnostic from a rumdl diagnostic on the same line. Consult the rumdl boundary research (ticket 03) for its diagnostic-code convention, as precedent to avoid collision.
- Decide push (`publishDiagnostics`) vs pull (`textDocument/diagnostic`, LSP 3.17+) model. Check `docs/refs/lsp_spec.md` for the pull-diagnostics capability. Decide which model Traces implements, or whether it implements both, gated by client capability negotiation (ticket 29).
- Decide debounce/recompute triggers: every `didChange` keystroke, or `didSave`, or a settle-timer. Stay within the performance targets ticket (33) and the concurrency model (ticket 12).
- Decide workspace-wide vs open-document-only diagnostics. Does an unresolved-link diagnostic fire for every note in the workspace on startup (expensive, but complete)? Or does it fire only for currently-open documents (cheap, but backlink-target notes that reference a broken link elsewhere stay silent until opened)?
- Confirm explicit non-overlap with rumdl: from ticket 03's findings, list the diagnostic categories rumdl already owns (its MD-rule lint catalogue). Make Traces' diagnostic set overlap it by zero, by design. Document the split for users who configure both servers.

## Decisions

### Round 1 (locked 2026-10-15; reviewed by three parallel review passes, findings in research §10)

1. **Scope (Q1-R)**: option B: push open docs + pull workspace with dirty-set/resultIds/refresh. Phase A is **document-level pull** (push only as fallback for pull-incapable clients; pushing non-empty to a pull-capable client clobbers pull). Phase B adds workspace pull + bounded ~10MB warm-up cache. All workspace-scoped decisions are conditional on open ticket 30 (multi-root).
2. **Push gate (Q2-R)**: gate push off when the client pulls (rumdl/ty pattern); publish empty once to invalidate; `workspace/diagnostic/refresh` is unconditional with swallowed error.
3. **Debounce (Q3-R; amended by Q3-R')**: T1 content/index 100ms; **T2 per-document publish ~50ms typical** (adaptive clamp [50ms, measured compute, 500ms], clangd D73949 shape; coalesced per URI; never republish an identical set; strengthened from 150ms on external evidence: clangd 50ms floor, Zed client 50ms, gopls tens of ms, ty 1 to 4ms; ts-ls is 200+50ms; client debounces stack, so a small server budget is mandatory); T3 workspace event-driven, with no timer. No `sleep` in any handler. Generalize 22's β publisher as-is for MVP; generation counters arrive with scope B inside the diagnostics module; separate lane and facade DirtySet are rejected. Workspace warm-up bypasses β's FIFO. Explicit rejections: on-type workspace sweeps (luau-lsp #1076), in-handler synchronous recompute (markdown-oxide #473 crash loop).
4. **Aggregation (Q4-R)**: no Pipeline abstraction; use plain fold functions over a protocol-free diagnostic type following `SchemaConstruction`'s collect-then-emit shape; `ls-types::Diagnostic` conversion happens only at the LSP boundary; module home pending ticket 34.
5. **Severity (Q5-R)**: 25 calibrates **only undeclared severities** (17, 18, 22's phase-1 classes, other §6.1 gaps); locked severities (22 Error import/from, 23 C-rules Information, etc.) are carved out. "Cannot parse/analyze at all" = Error for new decisions.
6. **Namespace (Q6-R)**: Scheme C: one `source: "traces"` + hierarchical `<feature>.<rule>` codes + pull `identifier: "traces"` + per-rule `codeDescription.href`. Use a single static registry table with `resolve(code, &OverrideSet)`; 15's `UnresolvedLinkPolicy` is demoted to override-key sugar (that wording is superseded by Q15-R2: the enum is deleted outright); per-ticket severity config types are rejected.
7. **Config (Q7-R)**: R-A: defaults in registry; overrides via editor-sourced O1 only in v1; project `[lsp.diagnostics]` defers to 31. 20's `[schemas.diagnostics]` gates emission, and the registry resolves severity (orthogonal).
8. **MD057 cession (Q8-R)**: cede standard-link existence (incl. image targets) to rumdl MD057, **plus a full 15 amendment**. Drop or repoint the code action. Flip the `15:198` flag. Make `.rumdl.toml` disable guidance the primary path (`15:209-213`). Narrow 15's "embed" to `![[..]]` only.
9. **MD066 cession (Q9-R)**: cede footnote undefined/unused/duplicate to MD066 (drop those three from 17). Footnote **self-reference** and **blockquoted-definition** stay Traces-owned (rumdl does not rule them).
10. **Cross-file anchors (Q10-R)**: claim them for Traces; suppress-when-target-missing (no double-report with `links.unresolved`); this needs ticket 11 spans + slug machinery.
11. **Change summary (Q11-R; primary reversed by Q11-R')**: reject expanding `RefreshReport` (Copy, baseline-pinned), and reject the raw-target reverse map (parallel `LinkResolver`). **Primary: facade old/new Arc snapshot-diff** (zero core changes): dirty set = FileMeta symmetric difference over `entries()` (pub, src/index/entry.rs:108); referrer set = union of old/new `FileEntry::inlinks()` (pub, entry.rs:168) per dirty path; retarget soundness: any edge move without the referrer changing implies a candidate file changed, observable in that dirty path's inlink union. O(N) per refresh rides the whole-tree scan `RefreshPlan::collect` already does. `FileDelta`/`InlinkDelta` `pub(crate)` widening is **demoted to fallback** (the value remains for exact-edge consumers like 41); facade-only trigger-list derivation is rejected (it misses retargets).
12. **Day rollover (Q12-R)**: ticket 18 is already resolved, so 25 **amends 18** to carry the timer/invalidation decision instead of deferring to a closed ticket.

### Round 2 (locked 2026-10-15; conflict/perf/design reviews, findings in research §11)

13. **Frontmatter Error (Q13-R2)**: keep 19's frontmatter-missing-delimiter Error; premises are corrected (MD041 Warning always fires, MD065 Warning on missing-closing shape only, "unsuppressible" softened to "suppressible only by disabling the rule"); Traces' Error is a frontmatter-parse code (`frontmatter.missing-delimiter`), not a heading judgment, so there is no duplication of ceded MD041/MD065; ship it as a one-paragraph coexistence note into 32.
14. **Docs href (Q14-R2)**: `codeDescription.href = https://github.com/JackMatanky/traces-pkm/blob/main/docs/diagnostics.md#<fragment>`, with `<fragment>` an explicit registry field equal to the code. docs/diagnostics.md carries one raw `<a id="<code>">` per rule (GitHub preserves dots in raw anchors). The rule table is generated from the registry with a golden-diff cargo test (public-api baseline pattern), so drift is impossible. One live browser check of dotted-fragment click-through is a pre-adoption task; fallback = shared slug function. No docs site exists, and the repo is public, so blob hrefs resolve.
15. **Escalation keys (Q15-R2)**: the registry enumerates link codes per kind (`links.wikilink.unresolved`, `links.wikilink.heading-ref.missing`, `links.wikilink.embed.missing`; `links.unresolved` is superseded and survives only as a docs grouping heading; there is no `links.markdown.*`, which is ceded to MD057). Override vocabulary is `hint|info|warn|error|off` on every key. `UnresolvedLinkPolicy` is deleted from the design outright (supersedes Q6-R's "sugar" wording; 15:155-166 amended). Registry shape = `enum DiagnosticRule` with `code()`, `default_severity()`, and `const ALL` (CliError precedent: exhaustiveness forces a severity on every new rule). Keep the dotted `<feature>.<rule>` spelling (do not inherit miette's `::`); disjointness = cheap ALL-iteration test. `OverrideSet` stays a deliberately thin boundary-built type that reuses only the `merge_optional` precedence idiom (NOT ConfigService machinery; `deny_unknown_fields` blocks smuggling O1 keys pre-31); record it as the exact type 31 must extend. Placement is inputs-pending on 34, with the constraint that the registry must be a leaf module reachable from feature modules and the LSP boundary. Adopt the BrokenLink side-channel as designed: shared internal parse returns `(Note, Vec<BrokenLinkRef>)`, `parse_markdown` wraps and discards. Sole production caller src/index/service.rs:276 is unaffected. Callback returns `None` never resolves, owner 15, coordination note to 11. Pseudo-outlinks and post-hoc second parse are rejected.

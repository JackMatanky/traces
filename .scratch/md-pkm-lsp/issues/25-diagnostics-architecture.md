## Question

Once link/reference resolution (ticket 15), schema validation (ticket 20), and query diagnostics (ticket 21) are each settled, decide the *unifying* diagnostics architecture:

- Aggregation: how per-feature diagnostic sources (unresolved links, ambiguous headings, schema violations, malformed queries, malformed templates) get merged into one `textDocument/publishDiagnostics` payload per document, with what severity levels and diagnostic-code namespacing (so a client/user can distinguish a Traces diagnostic from a rumdl diagnostic on the same line — consult the rumdl boundary research, ticket 03, for its diagnostic-code convention as precedent to avoid collision).
- Push (`publishDiagnostics`) vs pull (`textDocument/diagnostic`, LSP 3.17+) model — check `docs/refs/lsp_spec.md` for the pull-diagnostics capability and decide which Traces implements (or both, gated by client capability negotiation, ticket 29).
- Debounce/recompute triggers: on every `didChange` keystroke vs `didSave` vs a settle-timer — bounded by the performance targets ticket (33) and the concurrency model (ticket 12).
- Workspace-wide vs open-document-only diagnostics: does an unresolved-link diagnostic fire for every note in the workspace on startup (expensive, but complete) or only for currently-open documents (cheap, but backlink-target notes that reference a broken link elsewhere stay silent until opened)?
- Explicit non-overlap with rumdl: confirm from ticket 03's findings which diagnostic categories rumdl already owns (its MD-rule lint catalogue) and ensure Traces' diagnostic set has zero overlap by design, documenting the split for users configuring both servers.

## Decisions

### Round 1 (locked 2026-10-15; reviewed by three parallel review passes, findings in research §10)

1. **Scope (Q1-R)**: option B: push open docs + pull workspace with dirty-set/resultIds/refresh. Phase A is **document-level pull** (push only as fallback for pull-incapable clients; pushing non-empty to a pull-capable client clobbers pull). Phase B adds workspace pull + bounded ~10MB warm-up cache. All workspace-scoped decisions conditional on open ticket 30 (multi-root).
2. **Push gate (Q2-R)**: gate push off when the client pulls (rumdl/ty pattern); publish empty once to invalidate; `workspace/diagnostic/refresh` unconditional with swallowed error.
3. **Debounce (Q3-R; amended by Q3-R')**: T1 content/index 100ms; **T2 per-document publish ~50ms typical** (adaptive clamp [50ms, measured compute, 500ms], clangd D73949 shape; coalesced per URI; never republish an identical set; strengthened from 150ms on external evidence: clangd 50ms floor, Zed client 50ms, gopls tens of ms, ty 1 to 4ms; ts-ls is 200+50ms; client debounces stack, so a small server budget is mandatory); T3 workspace event-driven, no timer. No `sleep` in any handler. Generalize 22's β publisher as-is for MVP; generation counters arrive with scope B inside the diagnostics module; separate lane and facade DirtySet rejected. Workspace warm-up bypasses β's FIFO. Explicit rejections: on-type workspace sweeps (luau-lsp #1076), in-handler synchronous recompute (markdown-oxide #473 crash loop).
4. **Aggregation (Q4-R)**: no Pipeline abstraction; plain fold functions over a protocol-free diagnostic type following `SchemaConstruction`'s collect-then-emit shape; `ls-types::Diagnostic` conversion only at the LSP boundary; module home pending ticket 34.
5. **Severity (Q5-R)**: 25 calibrates **only undeclared severities** (17, 18, 22's phase-1 classes, other §6.1 gaps); locked severities (22 Error import/from, 23 C-rules Information, etc.) carved out. "Cannot parse/analyze at all" = Error for new decisions.
6. **Namespace (Q6-R)**: Scheme C: one `source: "traces"` + hierarchical `<feature>.<rule>` codes + pull `identifier: "traces"` + per-rule `codeDescription.href`. Single static registry table with `resolve(code, &OverrideSet)`; 15's `UnresolvedLinkPolicy` demoted to override-key sugar (wording superseded by Q15-R2: enum deleted outright); per-ticket severity config types rejected.
7. **Config (Q7-R)**: R-A: defaults in registry; overrides via editor-sourced O1 only in v1; project `[lsp.diagnostics]` deferred to 31. 20's `[schemas.diagnostics]` gates emission, registry resolves severity (orthogonal).
8. **MD057 cession (Q8-R)**: cede standard-link existence (incl. image targets) to rumdl MD057, **plus a full 15 amendment**: drop/repoint the code action, flip the `15:198` flag, make `.rumdl.toml` disable guidance the primary path (`15:209-213`), narrow 15's "embed" to `![[..]]` only.
9. **MD066 cession (Q9-R)**: cede footnote undefined/unused/duplicate to MD066 (drop those three from 17); footnote **self-reference** and **blockquoted-definition** stay Traces-owned (rumdl does not rule them).
10. **Cross-file anchors (Q10-R)**: claim for Traces; suppress-when-target-missing (no double-report with `links.unresolved`); requires ticket 11 spans + slug machinery.
11. **Change summary (Q11-R; primary reversed by Q11-R')**: reject expanding `RefreshReport` (Copy, baseline-pinned) and reject raw-target reverse map (parallel `LinkResolver`). **Primary: facade old/new Arc snapshot-diff** (zero core changes): dirty set = FileMeta symmetric difference over `entries()` (pub, src/index/entry.rs:108); referrer set = union of old/new `FileEntry::inlinks()` (pub, entry.rs:168) per dirty path; retarget soundness: any edge move without the referrer changing implies a candidate file changed, observable in that dirty path's inlink union. O(N) per refresh rides the whole-tree scan `RefreshPlan::collect` already does. `FileDelta`/`InlinkDelta` `pub(crate)` widening **demoted to fallback** (value remains for exact-edge consumers like 41); facade-only trigger-list derivation rejected (misses retargets).
12. **Day rollover (Q12-R)**: ticket 18 is already resolved, so 25 **amends 18** to carry the timer/invalidation decision rather than deferring to a closed ticket.

### Round 2 (locked 2026-10-15; conflict/perf/design reviews, findings in research §11)

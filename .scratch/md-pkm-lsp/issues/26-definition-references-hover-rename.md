# Definition, references, hover, rename & workspace-edit behavior

Type: grilling
Status: resolved
Blocked by: 11, 15, 16, 19, 22, 23
Assigned: agent

Research: [consolidated findings](../research/26-definition-references-hover-rename.md) (six subagent tracks: navigation substrate, entity abstraction, WorkspaceEdit mechanics, position/encoding/Uri plumbing, hover, prepareRename/rename semantics).

## Question

Once link/reference (15), tag (16), and frontmatter/inline-field (19) semantics are settled, and the span model (11) is in place, decide the shared mechanics every entity kind's navigation/edit capability rides on:

- A single internal "resolvable entity" abstraction (if warranted, per the "introduce abstractions only for real boundaries" preference, decide whether links/tags/headings/fields genuinely share enough resolution/edit shape to warrant one, or whether four independent, simpler implementations are actually less code) covering: locate-at-position, list-references, compute-rename-edit.
- `WorkspaceEdit` construction for rename: does Traces use `documentChanges` (versioned, LSP 3.16+ preferred form) or the plain `changes` map, check `docs/refs/lsp_spec.md`'s WorkspaceEdit section; decide `TextDocumentEdit` version-check policy given multiple files may be touched by a single rename (e.g. renaming a tag across 40 notes).
- Hover content: `MarkupContent` kind (`plaintext` vs `markdown`) and what's shown per entity kind (resolved path + first heading for a link target; resolved File Class fields for a schema-bound note; etc.), negotiated against client `hoverProvider`/`markdown` capability.
- Prepare-rename (`textDocument/prepareRename`) validity checks, e.g. refusing to offer rename when the cursor isn't actually on a renamable entity, or when the target is outside any confined root.

## Answer

Resolved by four grilling rounds (Q1-Q5, Q6-Q8, Q9-Q11, Q12), each round followed by a three-track stress test (conflict audit against the settled map, internet benchmark audit, codegraph design/alternatives audit) consolidated in the [research file](../research/26-definition-references-hover-rename.md) Parts VII, VIII, IX, X. Where research Parts I-VI contradict VII-X, the later parts win. Twelve decisions locked:

1. **Entity abstraction (Q1): one thin protocol-free nav spine, two enums, no behavior trait.** Core owns `nav::Occurrence { kind: OccurrenceKind, span: ByteSpan }` where variants carry domain payloads (`Wikilink(Link)`, `Embed(Link)`, `FrontmatterLink(Link)`, `Heading(Heading)`, `Tag(Tag)`, `FieldKey(FieldKey)`, ...), `nav::NavTarget { kind: TargetKind, doc: PathBuf, name_range: Option<ByteSpan>, scope_range: Option<ByteSpan> }` with the focus-containment invariant (`name_range` within `scope_range`) applying only when both exist, `TargetKind = Note | Heading | Tag | Footnote | Field | SchemaField | LinkDef | File` (LinkDef covers 15's reference-definition label spans; File covers images and schema TOMLs), and a `NavContext` facade (borrowed index/schema/config/content-resolver bundle, following the QueryService/SchemaService idiom) exposing `locate`/`resolve`/`candidates`/`references`/`rename`/`highlight`. Enum dispatch, exhaustive matches, no `ResolvableEntity` trait (rejected: forced stub arms for legitimate None-kinds, recreates Markdown Oxide's cross-product tax). `OccurrenceKind != TargetKind` (the load-bearing peer lesson). Per-kind logic stays in the domain modules that own the semantics. Boundary: no ls-types in core, module home pending 34 (same status as 25's fold). `nav::locate` classifies **navigation entities only**: 24's dispatcher, 23's raw scan, and 21/22 classifiers keep their own position logic, all feeding ONE renderer. Two named changes to existing code, budgeted: expose `LinkResolver` via a facade method and expose `paths_with_tag` the same way. Confinement predicate threaded through `resolve` (A7). Frontmatter-embedded wikilinks are first-class occurrences (A16).

2. **Resolution semantics (Q9): three-state, distance-nearest with explicit ties.** One `match_key`-keyed request-time `candidates(from, target) -> Vec<Match { path, distance }>` (candidates-with-distance; the `(nearest, alternatives)` shape re-encodes the tie bug into the type). The spine's `classify` derives `Resolution = Unresolved | Unique(target) | Ambiguous { kind: AmbiguityKind, candidates: Vec<NavTarget> }`: empty to Unresolved, strict argmin to Unique, tie to Ambiguous. "Distance" is the LCA **folder distance** (`FolderRef::distance_to`), `resolve()` unchanged for index build; `nearest_wins`/`ties_resolve_to_none` test suites remain the executable spec for the Unique side. AmbiguityKind = `StemTie | HeadingAnchor | PathTie` (PathTie added by Q12). Heading-anchor Ambiguous requires 15 D2's anchor matcher pinned as multi-match against pre-dedup slugs (written as an Amended-by-26 into 15). `RenameError::Ambiguous { kind, candidates: Vec<NavTarget> }` (thiserror, protocol-free). Hover gets candidates on demand via `candidates_at`, no `alternatives` side-channel on `Resolution`. Graph-vs-nav divergence recorded: the inlink graph keeps nearest-picked edges (backlink counts, 25's change-summary soundness, 27's counts, 28's rewrite targeting all consume them); navigation reports ties. Q9(ii) (revoking distance-picking) rejected as a 26-local switch.

3. **Ambiguity choke point and refusal taxonomy (Q6).** The ambiguity check lives in the spine's position-level entry points (`rename_at`/`prepare_rename_at`), never in handlers and structurally not in the single-target driver (MCP (36) gets it for free). Two-tier refusal taxonomy: `Ok(null)` = cursor off entity, non-renamable kind, alias/display side, confinement failure; `ResponseError(-32803 RequestFailed, human message)` = entity present but unsafe (ambiguity) or illegal `new_name`. `Ok(null)` covers only cursor-off-entity plus the four refusals; -32803 never mixed for the same operation class (amends 16's InvalidParams for tag rename). -32803 scope is rename/prepareRename **only**, never `textDocument/references` (erroring the read path contradicts 15's "ambiguity is normal in PKM"). Consumer matrix (written into this ticket): definition returns all candidates uncapped; hover renders a bounded list (first 5 + "+N more"); references returns the capped union; prepareRename/rename refuse with -32803; documentHighlight is document-local span matching and never errors on target ambiguity; unresolved hover is informational. Only link-shaped occurrences (stem ties, heading-anchor multi-match, path ties) plus DailyDate (18's folder/both/path modes produce stem ties, M3) can be Ambiguous; tags, fields, schema, footnotes resolve Unique/Unresolved only (negative pin written into 16). Distinct message text for heading ambiguity ("3 headings match in this note"). prepare checks the capability gate before ambiguity (gopls ordering).

4. **Comparison keys (Q10 + Q12): tiered `match_key`, byte-exact-first, fold-fallback.** One `match_key(s) -> Cow<str>` helper (quick-check borrow fast-path) in `src/path.rs`: NFC, then `char::to_lowercase`, then trailing NFC (idempotence pinned by property test; full casefold rejected, sigma divergence documented; simple-casefold alternative considered and declined for codebase consistency with `FieldKey::canonicalize`). Path keys fold `\` to `/` inside the same helper; non-UTF-8 paths take no fold step (byte-level, fixture owed). Applied at exactly two boundaries: index build (basename keys, exact-path hash map replacing the binary search on the resolver's lookup path only) and query side (link path/stem, request path, build); watcher-event paths normalized at intake. **Every lookup tier is byte-exact-first**: an exact-byte hit is final; the fold key is consulted only on miss; fold-tier ties, including multi-raw-per-folded-key collisions at the exact-path tier, become `Ambiguous { kind: PathTie }` (never raw-sorted-first; raw-sorted-first survives only for the NFC-equal exotic case). Rename self-exclusion rule (the file being renamed excluded from its own ambiguity candidates); case-only file rename = `RenameFile` with zero text edits (input to 28). Emit side: hash-map entry is (key, original path); all emits read the raw `FileMeta.path`; original spellings everywhere in output. Guard-rail verbatim: comparison keys only, never spans, never Uri/overlay keys, never edit payloads, never redb keys, never sort order, never I/O paths, never slug generation. New direct dep: `unicode-normalization 0.1` only, behind the one helper. Normalize at every intake boundary (ecosystem pattern: normalize-once-at-build, retain originals for output). Cost sold as correctness (12 to 300ns per key, ~10ms one-time index build, zero budget impact).

5. **References and the response cap (Q7 + Q11).** The union is computed at `references_at` orchestration as a union of **resolved occurrences** (per candidate, scan its inlink-implicated files for occurrences whose own file-relative resolution lands on that candidate; dedupe by (doc path, ByteSpan)); never a file-set union (that rewrites sibling same-stem notes on rename). `includeDeclaration` unions every candidate's declaration. Single-target driver stays the shared primitive so rename reuses it directly, structurally guaranteeing cap-free `EditSet`. Heading-tie union is complete and essential; stem-tie union is best-effort (tie-er notes produce no inlink edge today), documented with the multi-target-edge inlink-graph upgrade path recorded as its own future ticket, not a 26 rider. Cap: 5,000 soft cap scoped structurally to the `textDocument/references` response path only (two spine entry points; `EditSet` computation is never truncated), bounded collection in canonical order (files in path order, occurrences ascending, `take(5000)` with per-file early stop, capping work not just payload), truncation notice via `window/logMessage` (Info), named constant fed to 27/29, `partialResultToken` streaming upgrade path recorded for 29 (deliberate non-advertisement until then). Rationale is client-side (Neovim bufloads every referenced file: the measured 2.93s stall class), anchored honestly between clangd's 1,000 and VS Code's 20,000.

6. **WorkspaceEdit construction (Q2).** Core computes protocol-free `EditSet` (per-doc `(DocPath, Vec<Replacement { span, text }>)`, sorted and overlap-checked); the edge alone owns Uri/TextEdit conversion, capability gating, and `metadata` (map standing constraint). Two-tier serializer: emit `documentChanges` iff `advertised_documentChanges OR ops_present` (rust-analyzer-proven deviation; `changes` structurally cannot carry resource ops, Neovim advertises ops but not documentChanges). Versions: `Some(current_version)` for open/overlay docs, `null` for closed, **never 0 as a closed-file sentinel** (a client may legitimately open at version 0). Resource ops gated on `resourceOperations` alone; offered in prepareRename only when genuinely applicable (gopls "client does not support file renaming"). Full server-side pre-validation mandatory (no mainstream client rolls back; atomicity is a server obligation). `metadata.isRefactoring` set on multi-file cascades; change annotations skipped v1. In-house edit helper with apply-and-assert tests (no mature edit-application crate exists). Ownership: 26 owns server-initiated `RenameFile` for textDocument/rename on note targets (ordering: old-path edits, RenameFile, new-path edits); 28 owns client-initiated workspace/will*Files and the delete path. Post-rename refresh rides didChange + watched-file events into T1's 100ms coalesced refresh; ticket 13's single-file RefreshPlan constructor needs a **batch/multi-file constructor** (seam noted for the implementation spec). Uri policy: gate `scheme == "file"` at every boundary, absolute file URIs, echo client-spelled URIs verbatim, path-based cross-referencing, skip+log non-file schemes, no canonicalization machinery v1.

7. **Position encodings (Q5).** Negotiate utf-8-if-offered-else-utf-16 (first encoding in the client's ordered preference that Traces implements; never utf-32; default utf-16), echoed via `capabilities.positionEncoding`. One total `convert` module at the protocol boundary (`PositionEncoding`, `negotiate`, `to_lsp_position`, `to_lsp_range`, `to_byte_pos`), all functions clamping never panicking, inbound semantics = VS Code `offsetAt`. The same module is the miette bridge (miette SourceSpan is byte offset + len; no adapter crate needed). Whole-document ASCII fast path plus naive walk v1; `rust-analyzer` line-index crate upgrade route documented if hot. `byte_to_utf16_cu` retained as a thin `LineIndex` method so 19/23 prerequisite text stays true; 11's ropey branch deleted (14 resolved `BufferState { content: String, version: i32 }`, no rope; one LineIndex-backed helper serves disk and overlay via `ContentResolver::text_of`). BOM stripped once at ContentResolver. Encoding is an explicit parameter threaded from the session, never a global. This closes 11's open negotiation question and the 11/14 ropey inconsistency.

8. **Hover (Q3).** Kind: negotiated Markdown iff `contentFormat` contains Markdown (absent ⇒ PlainText); PlainText = stripped rendering of the same composed body, one composer two formatters, never raw markdown in a plaintext field. Architecture: one shared renderer plus per-entity producers over 24's per-(uri,version) content snapshot; `locate` shared with navigation, rendering never shared. Safe subset: 19's cross-IDE set plus strikethrough; banned: raw HTML, images, tables, `command:` links, theme icons, and **headings** (A12: schema-bound field hover renders the field name as bold, not H2, amending 19's internal inconsistency); one escaping helper (MS `escapeMarkdownSyntaxTokens` convention). Always set `range` to the token span when ticket-11 spans exist. Template hover renders 22's `Doc` and `Identified` tiers, suppresses only `None`, and shows an explicit degradation banner on construction failure (never silently empty). Caps are producer-owned: footnote preview ≤200 chars (17), inlinks ≤20, previews bounded, task hover one line; `isTrusted` is client-side only, the server never sets it. Wikilink/embed producer decided (A20): title + resolved path + bounded first-lines preview + inlink count, sourced from 19's refresh-time preview cache for disk files and ContentResolver for overlays (staleness ≤ T1 100ms), ambiguity labelling per the bounded candidate list. Heading-as-entity producer (N1): title + level + inlink count. Ambiguity lists bounded candidates rather than silently picking first (markdown-oxide's known wart). Non-resolvable states still hover, informational, never a prompt or code action (creation belongs to diagnostics). Budget: tightened to **<2ms target / <1ms stretch** (SOTA warm markdown hover is <1ms; 33's <10ms/<5ms row superseded here).

9. **prepareRename and per-entity rename (Q4).** Advertise `RenameOptions { prepare_provider: true }` iff the client announced prepareSupport (spec-mandated, Marksman pattern), else plain `true`; handlers registered unconditionally. Uniform `{ range, placeholder }` response. Refusal taxonomy per decision 3; rename **re-validates eligibility even after prepare succeeded** (clients may skip prepare, buffers may change). Per-kind matrix: wikilink occurrence rewrites the path/title/slug portion only (alias display preserved); standard-link ref/definition sites rewrite url/fragment only, display-text refuses (seam to 32); tags cascade prefixes via `replacen`, body `#`-aware and frontmatter syntax-aware, definition itself gets an edit; headings rewrite title text plus **all anchor occurrences** (cross-file `file.md#h`, same-file wikilink anchors, same-file standard-link fragments; rumdl MD051 line noted for 32; duplicate collision uniquifies `slug-1`, never refuses); footnotes are file-local find-replace (safe floor, implement first); frontmatter/inline field keys are note-local tier 1, FileClass-schema tier 2 deferred to 20's schema-TOML span work (amends 19); embeds ride the wikilink path with `!` outside the token range; RefLabel rename added (definition site + all three use forms, file-local); DailyDate refuses rename in prepare regardless of target-note existence; template/query identifiers non-renamable v1 (receipts into 21/22). `new_name` legality per kind validated at rename time (tag `Tag::parse`; heading reject `\n` and leading `#`; footnote reject spaces; field key `FieldKey` rules with case-only rename legal preserving author casing; wikilink target structural-resolver shape and reject collisions with existing stems). Cursor edges: alias side refuses; heading range excludes `#`s; fragment interior renames the target heading; code blocks excluded by AST construction. prepare range pins (A11): body tag includes `#` with placeholder `#projects/active`; frontmatter excludes `#` with placeholder `projects/active`. Errors: -32803 RequestFailed with human messages (never rust-analyzer's self-described-wrong -32602). Staleness: `Some(v)` for open docs keeps VS Code's `validateWorkspaceEdit` guard live; under sequential dispatch the prepare→rename pair is atomic server-side. Out-of-root: `Ok(null)` when the resolved target fails the confinement predicate (seam to 30).

10. **Concurrency and performance (A2, round-1).** Keep `concurrency_level(1)`; rename is the **sole handler permitted to exceed 100ms**; implement workDone `$/progress` for rename (sides with 33's allowance, amends 12's deferral; both written into those tickets). Blocking consequence (a 1s rename makes subsequent hovers wait) recorded with 41 as the structural fix. Budgets restated under 33's binding rows, byte-tiered not file-count-tiered: prepare <5ms (it's a locate); rename scaling by total bytes/occurrences (≤100ms @ ≤1MB, ≤1s @ ≤10MB); no refuse threshold v1 stands only because progress lands. Rename-at-scale evidence: tsserver 6s on 300-edit/190-file class, client-side apply ~0.5s; markdown notes are KB-scale so precomputed-span renames beat code LSPs. Zed rename smoke-test (prepare + rename error path) owed at implementation time; markdown-oxide documents "(not zed)" next to its rename features as the hazard evidence.

11. **NFKC rejected, slugger locked (Q8).** NFKC rejected everywhere (slug generation would produce rumdl MD051 false positives on Traces' own output and GitHub-rendered anchor mismatches; path matching would resolve links the OS/editor cannot open; 15 revoked title matching, so the Obsidian-title rationale was stale). Slug generation stays byte-exact GitHub (15 D2 + rumdl default + vendored github-slugger triple-lock). Live divergences named instead: filename/stem normalization (Obsidian, macOS) and NFD heading anchors. Unicode fixture set owed to 25: NFD heading vs NFC anchor, fullwidth, circled, ligature, emoji-in-title, NFC-equal duplicate filenames, CJK width tags, non-UTF-8 path, sigma, case-only rename; home = 15's slugger acceptance tests.
